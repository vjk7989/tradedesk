# TM2-6 review
## Code review (Sonnet)
Verdict: approve
- MEDIUM agent-runner/src/notify.ts:19-22 — Redaction list holds the untrimmed env values, but the URL and the sent text use the trimmed bot token (line 27 `.trim()`). If TELEGRAM_BOT_TOKEN has leading or trailing whitespace, such as a trailing newline, the exact string that ends up in the URL (and in any fetch error message echoing it) won't match `split(s)`, so the bot token would leak into the log line. The same applies to the MCP token if the existing job code trims it. Cheap fix: also add `s.trim()` to the secrets list (dedupe). Non-blocking; the tests only use clean values.
- LOW agent-runner/src/notify.ts:36-41 — Only the result body is capped at 3500 chars. The `error:` line is unbounded, so head + body can pass Telegram's 4096-char limit, and the API answers HTTP 400. That is logged and harmless to the job, but the notification is lost. Consider capping the error line too (say 300 chars). `.slice` can also split a UTF-16 surrogate pair; cosmetic.
- LOW agent-runner/src/notify.ts:43 — The non-2xx response body is never consumed or cancelled. Harmless for a single call, but `res.body?.cancel()` would be tidy.
- LOW agent-runner/test/tm2_6_notify.test.ts (timeout case) — The timeout is faked with an already-aborted signal, so no real timing is exercised. It does assert `AbortSignal.timeout(10_000)`, but only indirectly: a failing `expect` inside the mock is swallowed by notify's catch, and the test then fails on `toHaveBeenCalledTimes(1)`. Acceptable.
- INFO agent-runner/src/notify.ts:42 — `deps.fetch(...)` is called as a method, so `this` is the deps object. That is fine for Node's global fetch, but `const { fetch } = deps` would be more robust.
- INFO agent-runner/src/jobs.ts:130-139 — Notify is awaited inside the write try block, so a slow Telegram call delays the job's return by up to 10 s. This is bounded and inside its own try/catch, and `notifyTelegram` also never throws, so the status, the file and the return value are unaffected. Nothing is sent if the file write itself fails, which matches "after the report file is written".
- INFO coord/reports/TM2-6.md — Not in the brief's allowed list. It is the usual coordination report, and no source files are outside the list.
- OK Secrets: both tokens are redacted from the head, the error and the result before sending, and from every console.error. The URL appears only in the fetch call, never in a log except through a caught error message, which is redacted (modulo the whitespace edge case above). The missing-config warning names env vars only.
- OK Failure isolation: `notifyTelegram` never throws and `executeJob` adds a second try/catch. A throw, 4xx, 5xx or timeout leaves the job status, the file content and the return value unchanged (tested against a baseline file).
- OK Timeout: `AbortSignal.timeout(10_000)` is passed as `signal` to fetch.
- OK Truncation: the result is redacted and then sliced to 3500, which is tested with 9000 chars and counts exactly 3500.
- OK Schema strictness: unknown keys are rejected at both levels, array, null and non-string are rejected, and chatIdEnv must match an env-name regex. `notify` is omitted when absent. The tests cover 11 reject cases.
- OK Type safety: `notify?: {telegram:{chatIdEnv:string}}`, `fetch?: typeof fetch` and `Record<string, string|undefined>` env are typed; no `any` was added in src. I only read the diff and did not run tsc; the dev report says tsc, vitest and build are clean.
- OK No notify means no fetch (tested, and the real fetch is spied to fail). jobs.example.json only adds the `chatIdEnv: "TELEGRAM_CHAT_ID"` name, and a test checks it parses. The README names env vars only (TELEGRAM_BOT_TOKEN, chatIdEnv), never values.

## Fix plan (Opus), round 1, TM2-6
Edge tests (aa2cbf2, `agent-runner/test/tm2_6_notify.edge.test.ts`): 69 pass and 5 fail. All 5 are real bugs in `agent-runner/src/notify.ts`. Pull `tm2/TM2-6` first, and don't edit any test.
1. **Whitespace-padded bot token leaks** (MEDIUM, also found by the Sonnet review; notify.ts:20-25). The redaction list holds the raw env values, but the URL uses the trimmed token. Redact the trimmed value (and the raw one if it differs) for both the MCP token and the bot token.
2. **Overlapping tokens leak a fragment** (notify.ts:23). Redact the longest secret first, so a token that is a substring of another can't leave a tail.
3. **The MCP token can be sent as `chat_id`.** In `parseJobs` (jobs.ts notify check), refuse a `chatIdEnv` equal to the job's `mcp.tokenEnv` or to `TELEGRAM_BOT_TOKEN`. Also, at send time, skip with a redacted warning if the resolved chat id equals any secret (defence in depth).
4. **An emoji split at the 3500 cut** (notify.ts:40). After `slice(0, 3500)`, if the last code unit is a high surrogate, drop it.
5. **(LOW, from review)** Cap the `error:` line too, so the whole message stays under Telegram's 4096 limit, e.g. error ≤ 300 chars after redaction.
