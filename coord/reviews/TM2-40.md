## Findings
- INFO: The 4.5.94 floor is right. It is the version main locks, and the one known good on the #52 failure (4.5.64 imports toolz `_version.py`, which shells out to git, blocked by the sandbox). It is the lowest version that is verified, so no higher floor is needed. Only 4.5.64 is confirmed bad, and I did not bisect 4.5.65-4.5.93.
- INFO: A floor only blocks downgrades. Upgrades, including major ones, are unaffected, so Dependabot is still free to bump ccxt. A floor would only get in the way if a future ccxt release needed rolling back below 4.5.94. In that case, lower the specifier deliberately in the same PR. This is the intended behaviour.
- INFO: No interaction with the TM2-33 pandas ignore in .github/dependabot.yml. It matches only `dependency-name: "pandas"` for semver-major, and is untouched here.
- LOW: bt-service CI was still pending when I reviewed. The report claims 1931 passed locally. Confirm CI is green before merging, which is acceptance criterion 2.
- LOW: The report says the newer local uv (0.13.5) rewrites the lock to revision 5 and drops the scipy numpy markers, the same drift seen in #52. A floor does not prevent Dependabot from regenerating the lock with a newer uv, so lock-format churn may recur on later Dependabot PRs. It is out of scope here and should be watched.
- LOW: The proposed doc note ("generate uv.lock with the Dockerfile's uv, 0.9.26") is worthwhile but unwritten. A bt-service/README.md does not exist; the existing READMEs are the root README.md, agent-runner/ and e2e/. Suggest either creating a short bt-service/README.md "Dependencies / lockfile" section, or adding the note to docs/troubleshooting.md. Also, put a comment next to the uv version pin in bt-service/Dockerfile so the two stay in sync. Do this as a follow-up task, not in this PR, which the task file restricts to two files.
