## Findings
- MEDIUM, SECURITY.md:26: says the time limit is "30 s default". The production default is 60 s. trade-mcp/src/config.ts:106 sets executeTimeoutMs to 60000, clamped to 5000-900000 (deploy/.env.example:11, runbook:40). 30_000 is only the sandbox-internal fallback (sandbox/quickjs.ts:42). - LOW, SECURITY.md:40: says `search` and `execute` responses use `[REDACTED]`. server.ts:35 uses lowercase `[redacted]`. Only `audit.recent` and audit key redaction use `[REDACTED]` (sdk/bindings.ts:179, risk/audit.ts:55). The scrub also covers the bt token, not only OpenAlgo and MCP tokens. Wording fix only.
- LOW, SECURITY.md:41: "Upstream client errors have their own key or token redacted". Confirmed only for the OpenAlgo client (openalgo/client.ts:27). No equivalent redaction was found in the bt client. Name the OpenAlgo client.

- LOW, SECURITY.md:49: the lockfile claim is a documented convention (bt-service/README.md:6-7, uv==0.9.26), not an enforced check. CI uses an unpinned `uv sync` (the developer noted this). The wording "are generated with" is acceptable, but "by convention" would be more precise.
- INFO, SECURITY.md:47: PKCE is stored and validated through the MCP SDK (oauth/provider.ts:36,174 keep the code challenge; SDK pinned 1.32.2). The repo's own code does not implement the check.
- INFO: the brief's "secrets never in responses (dry-run, check, history)" is not claimed in SECURITY.md. Only readyz and the redaction scrub are. This is under-claiming, not overstating.
