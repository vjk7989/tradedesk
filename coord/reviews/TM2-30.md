Findings
- LOW main.ts:41,44: job name and MCP url are printed unredacted. A url may carry userinfo or a query token (validUrl allows it). A literal secret in jobs.json is not an env value, so this is outside the acceptance criteria. Passing the whole output through redact() is cheap.
- LOW main.ts:26: "claude-opus-5-5" is hardcoded, duplicating api.ts:48. The OpenAI default "gpt-5.5" is likewise duplicated. These will drift silently. Export the constants from api.ts and openai.ts. That is out of scope here, so follow-up only.
- LOW main.ts:35-38: there is no minimum length. A one-character env value would redact that character throughout the prompt. This matches notify.ts behaviour. Partially overlapping, non-nested secrets (suffix of A equals prefix of B) can leave a fragment, and encoded variants (base64, URL-encoded) are not covered. Same limitation as notify.ts.
- LOW test file: no tests for the trimmed variant, overlapping or nested secrets, blank values, or the Telegram envs. Those code paths are untested. Only the token and API key paths are covered.
- INFO: `--dry-run --jobs f` is rejected as a missing name because values starting with "--" are refused. This is reasonable.
