# O-17 review

## Security review (Sonnet)

Verdict: approve

1. checkStatic covers all data-free checks (engine.ts evaluate: kill switch, exchange, product, symbol deny/allow, qty, short-option qty, orders/day, orders/run, market hours/holidays). Texts unchanged: it shares evaluate() with checkOrder. Only notional, "price required", and dayPnl are skipped (staticOnly guards). OK.
2. Nothing removed. reserve() still calls checkOrder(), which runs evaluate(..., false) after the quote (bindings.ts place ~343, modify ~380). A static pass cannot bypass the full check.
3. Static denial throws "risk denied: ..." before any reserve, so audited() records "denied" (bindings.ts:226) and no counter is touched. reserve/commit/release are untouched.
4. Race: checkStatic is advisory and read-only (roll() only). The authoritative check plus the increment in reserve() is still synchronous, with no await between check and increment. Safe.
5. cancel and closePosition are untouched and do no risk check, so they stay allowed under the kill switch.
6. modify uses the same ordering (bindings.ts:374).

Low/informational:
- Mode/analyzer-ON check still runs after static checks, because it needs the network. Acceptable, and the report notes it.
- A combined static+notional failure now lists only the static reasons (fewer reasons shown, still denied).
- modify's static check includes the order-count checks. checkOrder already did this before, so there is no regression.
