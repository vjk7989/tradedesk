# O-6 review

## Code review (Sonnet)

Verdict: changes-needed (minor).

The new assertions are negative-only, so they are weaker than /memory/i. Any non-timeout failure passes them.
- sandbox.test.ts:58-63 and sandbox.edge.test.ts:298-306: a ReferenceError, "stack overflow" (quickjs.ts:67) or any other thrown error passes, and so does a broken cap that lets a later non-memory error surface. Syntax errors return early as "syntax error: ..." (quickjs.ts:58), which also passes.
- If the cap stops working, the infinite loop runs until the interrupt handler (quickjs.ts:68) or the timer (:177) fires, and fail() reports timeout. That is caught, but only after 20s. A finite allocator would pass silently.
- edge test 3 (:318-326) is the only positive control, but it allocates 1MB under a 4MB cap, so it does not prove the cap is what stopped the loop.

Minimal fix, still deterministic: add a control that runs the same finite allocation, for example 16 x 1MB retained, twice. With memoryBytes 64MB it must give ok:true. With 4MB it must give ok:false and error not matching /timeout|syntax|ReferenceError|stack/. Also assert error matches /memory/i OR /InternalError/.
