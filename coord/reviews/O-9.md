# O-9 review

## Security review (Sonnet)

**Verdict: changes-needed** (one medium).

1. Fail-closed check (quickjs.ts ~L98-106): runs after the deletes and before any user code, using only intrinsics. User code cannot influence it. `return fail` goes through finally, so the run aborts. OK.
2. Guest sizing (quickjs.ts ~L192-210), MEDIUM: sizeFn calls the global `JSON.stringify`, and the guest can replace it, or use toJSON, stateful getters or a Proxy, to report a small size. Then `vm.dump(argHandle)` builds the full host copy anyway. The host check (~L211+) runs after the copy exists, so the host-copy goal is defeated. The in-guest 1 MB cap is advisory only. Capture JSON.stringify before user code (as jsonParse is), or deep-measure without user hooks. Cycles and throwing toJSON are handled (Infinity). The host check is retained. No test covers a hostile toJSON, getter or overridden stringify (the Proxy in the test is only the init fake).
3. Result cap: applied before newString on the success path, and the message echoes only numbers, so it is safe. LOW: the rejection path (errMessage(e), ~L262) is uncapped, so a huge host error message is copied into the guest.
4. Dispose: jsonParse and guestSize are disposed before the context, and the runtime is disposed in finally. The 200-run loop exists, with a stated tolerance of 64 MB RSS and 32 MB external. OK.
5. Settle check: checkCeiling runs in pump and in both settle callbacks, and a test exists. LOW: it only sets a flag, so the settle path still allocates (newString/parse) before the next interrupt. The host stays alive, and the final check fails the run. OK.
