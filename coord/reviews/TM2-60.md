## 1. The fix (tushare_fundamentals.py:450-456)

I ran the same scenario (one pit row, 3 daily bars, `enrich_price_frames_with_fundamentals`) on pandas 3.1.1 and pandas 2.3.3, with the PR code and with origin/main.

| Case | main, pandas 3.1.1 | PR, pandas 3.1.1 | PR, pandas 2.3.3 |
|---|---|---|---|
| index unit s / ms / ns | MergeError | `[nan, 42, 42]` | `[nan, 42, 42]` |
| index unit us | ok | `[nan, 42, 42]` | `[nan, 42, 42]` |
| next_day intraday, us / ns | ns raises | `[nan, 42]` | `[nan, 42]` |
| reversed (unsorted) index, ns | MergeError | `[42, 42, nan]` | `[42, 42, nan]` |

- Correct: yes. `as_unit` is lossless for dates and is a no-op on pandas 2.3. Values are identical across pandas 2.3 and 3, and across units.
- Output index: unchanged. `merged.index = original_index` is untouched, and I confirmed the index dtype and equality are preserved for every unit.
- `normalize()`: unchanged. It still runs first, then `.as_unit("ns")` is applied to the result.
- Subdaily / next_day: the `+ Timedelta(1, "D")` shift happens at lines ~440-444, before the new `as_unit` line. It is value-based and unaffected.
- tz-aware index: still raises MergeError, identically before and after the PR (tz-aware left key vs tz-naive `_pit_date`). This is not a regression. See F2.
- The targeted tushare/fundamental tests pass (8 passed).
