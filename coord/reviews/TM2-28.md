# TM2-28 review notes (Opus, pre-review)

## Fix plan — round 1 (Opus): smoke leaks bt-service on every run (pre-existing; same file)
**Found:** 19 orphaned `uvicorn bt_service.app:app` processes on the build host, one per smoke run since TM2-19. All were cleaned up by hand.

**Cause:** `cleanup()` in e2e/smoke.mjs only sends SIGKILL to the direct child. For bt-service that child is `uv`, and the `uvicorn` grandchild it spawned survives. fake-openalgo and trade-mcp are direct `node` children, so they are fine.

**Fix**, e2e/smoke.mjs only:
1. On POSIX, `start()` spawns with `detached: true` so each server leads its own process group. Keep the pipes. Don't call `unref()`, because smoke must still wait on them.
2. `cleanup()` on POSIX does `process.kill(-c.pid, "SIGKILL")` (the group), wrapped in try/catch, falling back to `c.kill("SIGKILL")`. Windows keeps `taskkill /T /F`, which already kills the tree.
3. Call cleanup on every exit path: normal end, a failed step, an uncaught error and SIGINT. Check that the existing `finally` covers all of them, and add `process.on("exit")` if needed.
4. **Prove it.** Run smoke twice. After each run, `pgrep -f "uvicorn bt_service.app:app --port <that run's port>"` must find nothing. Also check after a forced failure: invert one assertion, run, confirm no survivors, then revert. Record all of this in the report.
