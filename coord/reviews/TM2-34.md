## Findings
1. HIGH - The documented pytest command does not run pandas 3.
   - `uv run --with "pandas>=3,<4" pytest ...` resolves `pytest` from the project venv.
   - Inside the test run, `pandas.__version__` is 2.3.3 and `Timedelta(5,"min").unit` is `ns`. The two files give 344 passed, 0 failed.
   - `python -c` in the same env does show 3.1.1, which hides the problem.
   - `uv run --with "pandas>=3,<4" python -m pytest ...` is the form that reproduces the 80 failures.
   - The task's Verify section requires reproducibility from the listed commands, so the report must use `python -m pytest`. Anyone following it as written would conclude pandas 3 is fully green.
2. MEDIUM - The P3-A and P3-B task splits mix source and test edits.
   - P3-A edits the loaders and also `tests/test_tm8_edge.py` and `tests/test_tm15_warnings_edge.py`.
   - P3-B edits `engines/base.py` and `tests/test_crypto_backtest.py`, and adds a new test file.
   - Project rule: only test writers edit tests. The report doesn't say so. Each brief must be split into a developer part (source only) and a test-writer part (test edits and new tests), run in order.
   - P3-A's acceptance is "the 80 failures pass" while the generic-warning test is deleted or xfailed. The developer must not touch that. It is a test-writer decision.
   - Group 1's "relax the tests" option and group 2's "make tests unit-agnostic" option are test-writer work.
3. MEDIUM - Group 2's recommendation is a policy decision, not a plain fix.
   - It is labelled S-M, but the report itself says the decision matters more than the edit. Forcing ns in `resample_bars` and the loaders changes a public output dtype.
   - The brief needs an explicit owner sign-off on the policy before P3-A starts. Otherwise the 57 cases could be fixed by loosening tests alone, which leaves the mixed-unit risk open.
4. LOW - The `.values.view("i8")` mixed-unit latent risk (`engines/base.py:298`) is real. It is only covered by the new regression test in P3-B.
   - That is sensible. The order should be stated: P3-B's source fix should land before or with P3-A.
   - `rebalance_mask.py` is already safe via `as_unit("ns")`.
5. LOW - Group 1's source site (`_TIMEFRAME_DELTA`) is only used as a tolerance, so it is value-equal across units. The report says so, and I agree. A fix limited to tests is defensible there.
6. INFO - Zero failures in groups 4-7 are claimed and plausible. Only the 2-file subset was verified here. The 647s full-suite counts are the author's.
7. INFO - Base 6af7094 is behind current main. bt-service is unchanged there, and results are the same on main.
