## Findings

- **INFO (walkforward.py `_bars`, ~L44-47): bar counting is valid.** `run_backtest` passes only start/end/interval and the engine writes one equity row per evaluated bar over that window. There is no warmup or evaluation_start offset in the config, so `len(equity)` is the evaluated-bar count. Downsampling caps it at 500, and the threshold is 10, so a thin run (<10) is never affected by it. Right measure for "thin".
- **INFO (`_bars`/`_thin`): empty equity should warn, so keep "thin (0 bars)".** A run reaching this point has `ok: True` (no-equity-file and failed runs already return `ok: False` via `_fail`) yet has 0 points, for example a header-only equity.csv. That is the thinnest case, and silently scoring it is the bug this task exists to fix. It is not a "no data" error path. The 33 TM2-38 edge failures are therefore an artifact of those fakes returning `equity: []`, not a product regression. Recommendation: the test writer should give those fakes (and the oracle copy of old walk_forward) >=10 equity points, or make the oracle compare ignoring `thin` warnings. Do not weaken the code.
- **INFO (~L155, 157): judging the winner is right.** All candidates for a fold run on the same data window and differ only in signal parameters, so bar counts match across candidates. The winner's run is always ok with a finite score, which makes it the safe one to judge, and it gives exactly one train warning per fold. Judging every candidate would duplicate warnings; the train-data length is not available without a new fetch (brief forbids). Train warning is emitted after selection and before the test run, so it is also kept when the test run fails or the budget expires.
- **INFO: warnings only.** Scores, `best_idx`, folds, summary and `ok` are untouched; `test_scores_unchanged_by_thinness` covers it.
- **INFO: budget returns.** Both time-budget returns now include `warnings`; all four failure returns are `{ok, error, folds, warnings}`. Test pins the key set.
- **INFO: wording** matches the brief: `fold <i>: thin <train|test> window (<n> bars < 10)`. MIN_FOLD_BARS is a documented module constant.
- **INFO: no existing test edited**; the PR touches walkforward.py, the new test file and the report only. The TM2-31, TM2-38 pin and other existing-test updates are left to the test writer as the brief says.
- **LOW (`_bars`): a run with no list `equity` key is silently not counted** (None -> no warning), while `[]` warns. Inconsistent but harmless: run_backtest always returns a list. Fine to leave; could treat missing as 0 for consistency.
- **LOW (behaviour note): with the daily interval, any `test_days` < 14 (including MIN_TEST_DAYS=5) can never reach 10 bars, so every fold warns "thin test window".** Intended by the brief, but callers using short test windows get one warning per fold. Doc line should say so.
- **LOW: docs/backtesting.md** needs the one line the developer proposed; not edited here, per brief.
