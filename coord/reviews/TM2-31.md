# TM2-31 review (PR #63): walk-forward over india_options and composite baskets

Verdict: APPROVE with follow-ups. No BLOCKER or HIGH. Tests-only scope is respected; the main weakness is runtime (about 6 min) and a thin "warning" AC.

## Scope
Diff is exactly the new test file, three `tm2_31_*` fixture CSVs (22 rows each) and the report. `walkforward.py` and the engines are untouched. Fixtures are hand-generated synthetic series (no real data or licensing issue). Symbol format `NIFTY25NOV24000CE@NFO` matches docs/backtesting.md. 2025-11-25 is the last Tuesday of Nov 2025, so a Tuesday expiry is plausible.

## Findings
- MEDIUM, test_tm2_31_wf_options.py (whole file): runtime is about 5.9 min on my run (354s pytest). Heavy items: module fixture ce_only setup 76s, the after-expiry test 75s, three composite tests about 54s each. This roughly doubles the bt-service CI time (3-5 min before). Trim: use 2 candidates instead of 3, share one `_wf` result for the two composite/mapped runs, make the after-expiry test reuse `ce_only`'s range by setting a smaller range (or monkeypatch to a single candidate), and drop the mapped-only test (covered by the 3-symbol one). Target is under 2 min. Alternatively mark with a `slow` marker if the repo has one.
- MEDIUM, test_tm2_31_wf_options.py:21-29: the strategy is a constant weight, and every fold picks `w=0.3`, so the "exact chosen params" assertion never discriminates between candidates (it only shows the max weight wins on an up-trending train window). Add a candidate or a fixture shape where fold 1 and fold 2 choose different params, otherwise a selection bug would not be caught.
- MEDIUM, test_tm2_31_wf_options.py:101-112: the "no look-ahead" evidence is only that the fold-2 standalone run matches the fold metrics. That does show the test run is self-contained, but it does not show fold 1's choice ignores data after its boundary. A stronger check: truncate or perturb the fixture after 2025-11-16 and assert fold 1's `chosen` and `train_score` are unchanged. Also the standalone call ends 11-25 while the fold ends 11-26 (half-open); fine, but say so in a comment.
- MEDIUM, AC "clear warning, not a crash" (test_tm2_31_wf_options.py:142-168): met only as a clear error for empty folds (`ok:false`, names the fold and the missing symbol). Thin folds (5 train bars, 4 test bars) run silently and `res["warnings"] == []` is asserted at :70 for the main cases, which pins the lack of a warning. I read the AC as a warning-level signal for thin data; the PR delivers a hard failure for empty and nothing for thin. Recommend a small follow-up src task: add `fold i: only N bars for <symbol> in train/test` to `warnings` below a threshold, and consider skipping an empty fold with a warning rather than failing the run. Not a blocker for this tests-only PR since the report states the gap honestly, but the brief's AC wording should be re-confirmed with the owner.
- MEDIUM, dropped folds (walkforward.py:164, pinned at test_walkforward.py:130 and test_walkforward_edge.py:520): a failed test run returns `{ok:false, error}` and discards completed folds. For the post-expiry case (test at :162) the user loses fold 0 and fold 1 results because the third fold lands after the contract expired. This is a real usability bug for options, since a range extending past the last expiry is the normal case. Worth a follow-up that returns `ok:false` plus the completed `folds`, or ends gracefully with a warning; it needs the two existing pins updated.
- LOW, test_tm2_31_wf_options.py:92-139: expected values are long full-precision literals taken from a run. They are deterministic and rel=1e-9 is fine, but they are characterization (golden) values, not independently derived. The expiry-settlement test (:108-112) is the one with hand-checkable numbers (price 352.33, qty 12, pnl -16348.8, reason "expiry"); keep that. Consider rounding the goldens to 1e-6 to reduce brittleness against harmless float-order changes.
- LOW, test_tm2_31_wf_options.py:43-50: env fixture restores env vars manually; `monkeypatch` with a module-scoped `pytest.MonkeyPatch()` would be simpler. Cosmetic.
- INFO, warnings: I ran `uv run pytest -q tests/test_tm2_31_wf_options.py -W default` on a clone of the PR head. Result: 8 passed in 354s, with no warnings summary at all. The new tests emit no warnings. The 404 vs 403 difference in the full-suite total comes from elsewhere (an existing test or ordering/dateutil deprecation count, or main moving); it is not caused by this file.
- INFO, positive: oos_equity checks (:81-87) for chained windows, no train dates in OOS equity and last date at the expiry are meaningful; the report's note about the inconsistent-underlying fixture trap is useful.
