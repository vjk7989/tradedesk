# O-13 review

## Security review (Sonnet)
Verdict: changes-needed (one medium bypass; otherwise sound)

1. Wrapper bypass
- MEDIUM quickjs.ts (wrapper, ~l.160): guard runs only if `typeof text === "string"`. `JSON.parse({toString(){return big}})` or `JSON.parse([big])` coerces to a big string and skips the guard. Fix: `const s = String(text)` once, pass s to P, test s.length.
- Not bypassable: original P lives in a closure, installed before guest code (before execute's evalCode at l.328). Reflect.apply, .call, .bind and Function.prototype tricks all hit the wrapper. Deleting or redefining JSON.parse only removes the guest's own parser (no native original reachable). Redefining Error cannot stop the throw. The host `jsonParse` handle (l.138) and S are host-side only.
- LOW: the check runs after the parse, so one parse can still peak at cap + transient (bounded by the 16 MB headroom and post-run check).

2. InternalError rethrow (l.144)
- INFO: a guest can `new InternalError()` from toJSON. The call is then rejected as "too large" (l.221-226) instead of "not serialisable" (l.248). Both reject, so there is no fail-open; only the message is wrong.

3. Other native allocators
- MEDIUM: repeat, padEnd, join, concat, replace, RegExp, sort, Array.from, JSON.stringify and template literals can all do the same. Memory is mostly counted by the QuickJS limit (live strings/arrays), but transient buffers are not. Loops of a few large calls run few bytecodes, so the interrupt (fixed ~10k counter in C) rarely fires.
- quickjs-emscripten 0.32 has no poll-interval option, only setInterruptHandler. Wrapping every native is impractical.
- Recommend: keep the interrupt check, and enforce a hard cap with a custom WebAssembly.Memory `maximum` via newVariant `wasmMemory` (index.d.ts:1876). This kills growth at the source. Alternatively run in a worker or child with a resource limit. Accept the current fix as a stopgap; document the limitation (ADR-18).
