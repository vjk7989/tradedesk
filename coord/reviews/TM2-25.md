## Findings
- MEDIUM search.ts:29-34: matching is OR across tokens, with header order and no ranking. A multi-word query such as "risk denied" or "short option" matches any line containing any token ("option", "risk", "market" all occur in CRYPTO_NOTE lines), so unrelated crypto lines can fill the 8-line cap and push out the line the query wanted. It works today only because the header is short. Prefer ranking by number of tokens matched, then header order. Follow-up is fine, it is not a regression against the brief ("any header line matches a token").
- LOW tm2_25_search_header.test.ts:25-27: the readonly tests never assert the security property. Nothing checks `not.toContain("declare namespace trade")` or `function place(` for a readonly query that also hits the header. Add those. The O-5 file covers it once updated, but the new test should pin it too.
- LOW tm2_25_search_header.test.ts:18-21: the "market closed" and "kill switch" tests are weak. "market closed" only checks that "// Rules:" appears, not which line, and it is likely matching crypto "market hours". "kill switch" does not assert that there is no Rules block, which would pin the gap.
- LOW tm2_25_search_header.test.ts: no test pins byte-identity for a no-header-match query beyond `not.toContain("// Rules:")`. A snapshot, or a comparison against `render` of the same hits, would give the AC real coverage.
