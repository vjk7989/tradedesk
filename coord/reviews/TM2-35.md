## Findings

### HIGH-1 Running-server race: `exec ... --force` then restart is NOT safe (provider.ts:122-141 callers; revoke-cli.ts:17, report runbook line)
The running server holds the full store in memory and rewrites the whole file via `persist()` on: `/register` (provider.ts:161), `/authorize` (180), failed login (211), successful login (226), code exchange (251), `issue()` on every token/refresh (288), `exchangeRefreshToken` reuse detection (268) and `/revoke` (315). `/register` and `/authorize` are unauthenticated and public, so any anonymous request, a connector doing a routine refresh, or the attacker replaying a leaked refresh token in the window rewrites oauth.json from memory and resurrects every revoked token before the operator restarts. Worse, the attacker's refresh in that window also mints a fresh token pair that persists. Until restart, the live process also keeps accepting the old access tokens (verifyAccessToken reads memory only, line 299). The window is "until the operator types the restart", but during an incident that is exactly when the attacker is active.
Recommendation: the only safe procedure is stop -> run -> start. Remove the `docker compose exec ... --force` suggestion from the CLI message and the runbook, or at minimum say loudly: "--force with the server running is NOT safe: any request can rewrite oauth.json from memory and undo the revoke; old tokens stay valid in the live process until restart. Stop trade-mcp first." Prefer making `--force` mean "I have stopped the server" rather than "run alongside it".

### HIGH-2 Documented stop -> run command does not work with this deployment (report runbook line; deploy/docker-compose.yml:51-54)
The report's procedure is `docker compose stop trade-mcp && DATA_DIR=<dir> npm run oauth:revoke-all -- --force` on the host. The store lives in the named volume `trade_mcp_data` mounted at `/data`; there is no host `<dir>`, and the host has no built `dist`. `docker compose exec` cannot run in a stopped container. The workable path is a one-off container on the same volume, which exists and has the right DATA_DIR and user:
`docker compose stop trade-mcp && docker compose run --rm --no-deps trade-mcp node dist/src/oauth/revoke-cli.js --force && docker compose start trade-mcp`
(`run` replaces the CMD, so the server does not start; confirm this on the VPS). This must go in docs/vps-runbook.md section 13, which the PR does not touch (section 13 has no revoke text; coord brief said to document it).

### MEDIUM-1 Wrong-shape-but-valid JSON wipes registered clients (revoke-cli.ts:28-33, provider.ts:93-117)
The corrupt-store guard only does `JSON.parse`. A file that parses but is not an object (`null`, `[]`, `"x"`, `0`) makes the constructor throw at `d.clients` (TypeError for null) inside the try, hits the catch that clears everything, and `revokeAll()` then persists an empty store: all clients lost, contrary to the stated intent. Fix in the CLI: require a plain object (and ideally that `clients` is an object) before constructing the provider; otherwise exit 1 untouched. Add a test with `null`/`[]`.

### MEDIUM-2 Shared `oauth.json.tmp` name (provider.ts:133)
Server and CLI both write `oauth.json.tmp`. With the server running (the --force path) concurrent writes can interleave or one rename can fail with ENOENT, which in the CLI throws an uncaught exception with a stack trace (exit 1, same code as corrupt). Not fixable within the "revokeAll only" scope; moot if HIGH-1 is adopted (server stopped). Mention only.

### LOW-1 Exit codes and usage not in the runbook; uncaught errors share exit 1 (revoke-cli.ts:20,32)
Document 0/1/2 in the runbook. An unexpected exception (e.g. EACCES on /data) also exits 1 with a stack trace; wrap `run` in a try/catch to print a one-line error and exit with a third code, so scripts can tell "corrupt store" from "could not write".

### LOW-2 Refusal text is misleading when the server is already stopped (revoke-cli.ts:12-19)
Even in the correct stop -> run flow the operator must pass `--force`, but the message frames it as a risk override. Reword once HIGH-1 is settled (e.g. "--force: confirms trade-mcp is stopped").

### LOW-3 `npm run` in the production image (trade-mcp/Dockerfile)
Runtime stage is node:22-alpine, so npm exists, `package.json` is copied to /app (so the script resolves), `dist` is built from tsconfig.build.json with include `src` and rootDir `.`, so `dist/src/oauth/revoke-cli.js` exists, and user `node` can write /data (chown'd). So it works after an image rebuild; but `npm run` as the unprivileged user writes npm logs/cache under the home dir and adds nothing. Recommend `node dist/src/oauth/revoke-cli.js --force` directly in docs, as in HIGH-2. The image must be rebuilt (`docker compose build trade-mcp`) before the command exists; say so.

### INFO-1 Readonly token: output says both static tokens are unaffected but only asks to rotate MCP_TOKEN (revoke-cli.ts:25,44). Suggest "rotate MCP_TOKEN (and MCP_TOKEN_READONLY if exposed)".
### INFO-2 Author reported one O-8 sandbox timeout under load; passes alone; unrelated.
### INFO-3 Test quality is good: end-to-end through the real HTTP server and restart, covers clients/limiter survival, refuse-without-force, missing and corrupt store. Missing: wrong-shape store (MEDIUM-1).
