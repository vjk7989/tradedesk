# TM2-45 review (independent): central ns normaliser

**Verdict: APPROVE-WITH-NITS (no BLOCKER/HIGH).** Reviewed head 583c607. The choke point is correct and complete for registered loaders. Gaps are one missing acceptance test (MEDIUM) and a few non-blocking notes.

## Verified
- **Every loader is registered.** All 27 loader classes in `loaders/` carry `@register`; binance is a `CcxtDataLoader` subclass that does not override `fetch`, so it inherits the wrapped parent fetch. Imported them all under pandas 3.1.1: `LOADER_REGISTRY` has 27 entries, 0 with an unwrapped `fetch`.
- **Callers.** Every `.fetch(` call site (runner 2055/2086/2112/2225/2284/2422, benchmark, correlation, loader_health, engines/base.py:1017, options_portfolio:254) goes through a registered class or the runner's snapshot wrapper. The snapshot wrapper's `_inner` is a registered loader, and its `_data` comes from earlier fetches. No bypass found.
- **Subclass override.** Probed: a registered subclass defining its own `fetch` is wrapped, and its signature and docstring are preserved (`inspect.signature`, `__doc__`). A registered subclass that inherits a wrapped parent fetch skips the second wrap (idempotent, correct), and the parent is unaffected. The `_ns_normalised` flag is set on the wrapper only. Double-wrapping via `super().fetch` is harmless.
- **Wrapper.** `functools.wraps` is used, exceptions propagate, and dict, frame, None, int and list inputs all behave (non-frames pass through). Order is `loader_read` first, then ns, and `gateway_public_read` is carried over by `wraps`.
- **Copies.** On an ns index `_to_ns_index` returns the same object (`is` True, no copy). Otherwise it does `copy(deep=False)`, and `np.shares_memory` is True, so there is no data copy.
- **tz / NaT / attrs.** A tz-aware us index with NaT becomes `datetime64[ns, Asia/Kolkata]`, NaT preserved. `df.attrs` is preserved. Datetime columns are untouched (a `datetime` column stays `datetime64[us]`).
- **resample_bars empty path.** Under pandas 3 the empty frame with 1W/1M comes back ns, as intended. Non-resampled intervals return the frame as-is (the wrapper handles those). Correct. The expected strict XPASS follows.
- **industry_loader.** `in_dt`/`out_dt` and the index are pinned to ns before every `to_numpy(int64)`/`asi8`. On 2.3 these are no-ops, so values are unchanged. Covers all three int64 operands.
- **Tests.** No existing tests edited. Pandas 2.3 suite: 1645 passed before the only failure, which is `test_tm2_41_units.py::test_resample_bars_empty_non_ns_frame_is_pinned_to_ns` (strict XPASS, expected). Full pandas 2.3 run: 2207 passed, 1 skipped, 6 xfailed, 1 failed (that XPASS), 403 warnings.

## Findings
- **MEDIUM** The PR contains no `tests/test_tm2_45_ns_normaliser.py` (brief: new file by the test writer). The acceptance criteria (fake us loader plus mocked ccxt under pandas 3) are therefore not evidenced in the PR. Add it, or confirm it lands in a companion PR, before TM2-43 relies on this.
- **LOW** History: commit 14e2261 added 113 `__pycache__/*.pyc` files (removed in 583c607). The tree diff is clean, but merge with squash, not a merge commit, to keep them out of main's history.
- **LOW** registry.py `_to_ns_index`: a `Series` with a DatetimeIndex is handled; a `Series` with a non-Datetime index passes through, fine. A `MultiIndex` whose level is datetime is not normalised (none observed in loaders).
- **INFO** Non-registered paths are not covered, as the report says: `fundamentals_loader`/`valuation_loader` panels reindex to the caller's target index (already ns through fetch), and `eastmoney_client.fetch_kline` is only used inside the registered eastmoney loader. No loader exposes the time axis as a column; all use the index.
- **INFO** The wrapper only guards `fetch`; loader code that calls its own helpers internally still builds us frames, which is fine because they are normalised on exit.
- **INFO** `register()` is a decorator: any future loader registered by other means (direct `LOADER_REGISTRY[...] =`) would bypass the wrapper. Currently none.

Probe (pandas 3.1.1, scratchpad): wrapped subclass fetch -> `datetime64[ns]`, tz+NaT frame -> `datetime64[ns, Asia/Kolkata]` / NaT, empty 1W/1M -> `datetime64[ns]`.
