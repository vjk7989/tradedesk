# TM2-72 report: paper-bot per-symbol P&L + CSV export

Read-only presentation change. Files: `paper-bot/paper_bot/web.py`, `paper-bot/paper_bot/stats.py`. Engine, strategy and fills untouched. No tests added or edited.

## Design
- `stats.per_symbol(conn, cfg)`: one dict per symbol (config symbols first, then any extra in the DB): realised, unrealised, trades (all fills), closed_trades, win_rate, side (`flat` if no position), last_decision (latest row by id).
- Win rate, same definition as the global card (`summary`): closed trades with pnl > 0 / closed trades, `-` if none.
- Unrealised: `(mark - entry) * qty * (+1 long / -1 short)`, the engine's snapshot formula.
- Realised: `sum(close pnl) - entry_fee of the still-open position`. Global realised is `cash - capital`; cash pays every open fee when it is charged, while a close's pnl only subtracts the entry fee of the position it closes. So the open position's entry fee must be added to make symbols sum to the global figure.
- Dashboard: "Per symbol" card row (realised, unrealised, trades, win rate, side, last decision action + reason, all HTML-escaped) and download links that carry the current valid filters.
- `web.valid_filters(cfg, symbol, action)` is the single whitelist (symbol in cfg.symbols, action in ACTIONS; otherwise `""` = all). `render()` now calls it and both CSV routes call it, so an invalid filter behaves exactly like the HTML route: silently ignored, all rows, status 200.
- `/api/trades.csv`, `/api/decisions.csv`: all rows newest first (`ORDER BY id DESC`), `csv` module, CRLF line endings, `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="..."`, `Cache-Control: no-store`. Columns are DB columns plus ISO UTC time columns. The `action` filter on trades (trades have no action column) keeps fills written by a decision with that action (same ts and symbol): `reverse` returns both legs, `hold`/`skip` return none.
- Auth: the app has no auth of its own; `/api/*` is protected only by Caddy basic auth in front. Nothing in the app was changed, and the new routes live under `/api/` so they fall under the same Caddy rule. (Caddyfile not touched or modified.)
- Secrets: output contains only DB columns; no config, env or path values.

## CSV-injection decision
Numbers stay numbers; every string is sanitised. A cell is prefixed with `'` if its string form starts with `=`, `+`, `-`, `@`, tab, CR (and LF). Negative P&L such as `-12.5` is a Python float, not a string, so it is written as `-12.5` and stays numeric in spreadsheets. This closes the gap because a formula cannot start from a float (floats serialise as `-12.5`, `1e-05`, never `=...`), while all free text (`reason`, `symbol`, `side`, `kind`, `signal`, `action`) is always sanitised. A numeric-looking string in a TEXT column is still a str, so it is sanitised. Trade-off: a hostile text value like `-5` gets a `'`, which is intended.

## Review

Reviewer: independent (Claude). Verdict: **CHANGES REQUESTED** (one blocking performance finding; everything else passes).

1. **BLOCKING** `paper-bot/paper_bot/web.py:118` - the trades `action` filter is a correlated `EXISTS` on `decisions(ts, symbol)` with no index, so it is O(trades x decisions). Measured on a scratch DB with 50k decisions and 1.2k trades (about 3 months of 2 symbols at 5m): `/api/trades.csv?action=open` took 35 s of CPU, versus 0.12 s unfiltered. The dashboard's download links carry the active action filter (`render`, the `qs` line), so one click after using the filter hits this, and the cost grows with the data. Fix: build the set once (`... AND (ts, symbol) IN (SELECT ts, symbol FROM decisions WHERE action=?)`, or a JOIN) or `CREATE INDEX` on decisions(ts, symbol) (schema is in db.py, outside the file list, so prefer the query change). Re-measure.
2. Suite: `uv sync` then `uv run pytest -q` run by me on the branch head: **85 passed, 1 warning** (httpx/starlette deprecation, pre-existing). No tests were added although the brief asked for `paper-bot/tests/test_tm2_72_dashboard.py` (fixtures for empty, one symbol, two symbols, reversal; CSV round-trip; injection). **BLOCKING-ish / should fix**: the acceptance criteria call for that file, and the dev's report says "No tests added". Please add it (it is also the place to lock in finding 1 and 5). uv.lock unchanged; engine files untouched (diff touches only web.py, stats.py and the report).
3. Existing behaviour unchanged (non-blocking, PASS). I loaded `origin/main` web.py as a separate package and compared against the branch on a fixture DB with open and closed trades, via TestClient: `/`, `?symbol=A`, `?symbol=ZZ`, `?symbol=` (empty), `?action=open`, `?action=bogus`, `?action=OPEN`, `?symbol=a`, symbol+action, `?symbol=%3Cscript%3E`, repeated `symbol` params. All return 200 on both, and the HTML is byte-identical once the new "Per symbol" block and download links are removed. Empty DB also identical. Invalid filters are silently treated as all, as before.
4. Per-symbol numbers (PASS, non-blocking notes). Fee accounting in engine.py: `_open` charges the fee to cash; `_close` adds gross - close fee to cash and writes pnl = gross - close fee - entry_fee of the closed position. So each fee is counted exactly once: closed positions' entry fees inside close pnl, the open position's entry fee via the `- entry_fee` term at `stats.py` (realised line in `per_symbol`). I reconciled with the real Engine primitives (open, profitable close, short open, reversal to long with a loss, symbol B open-only, symbol C skip-only): global realised 5.119093331854 vs sum of symbols 5.119093331855, cash - capital 5.119093331854, unrealised and trades (6) and closed trades (2) match. The engine-driven reversal fixture also reconciles. Win rate 50% (1 of 2 closes), flat/long/short side and last decision with reason are right; a symbol with only an open position shows realised -0.50 (its entry fee), win rate "-". Notes: (a) showing "realised -0.50" on a symbol that has no closed trade will confuse the owner; suggest the label "realised (incl. open entry fee)" or a tooltip. (b) Global realised comes from the last equity snapshot while per-symbol uses live positions, so the two can differ for a moment between a symbol's commit and the end-of-tick snapshot. Cosmetic. (c) `stats.py:41` operator precedence: `-` binds tighter than `|`, so only `last` is filtered against config symbols; harmless because `dict.fromkeys` dedups, but the parentheses are misleading.
5. CSV routes (PASS, with notes). Newest first (`ORDER BY id DESC`), all rows, headers `text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="..."`, `Cache-Control: no-store`; invalid filter gives all rows with 200 (same whitelist function as HTML). Trades `action` match by (ts, symbol) (`web.py:118`): not robust in principle. Constructed cases: a second decision row sharing ts and symbol with a reversal (action `hold`) makes the reversal's open and close fills appear under `action=hold`; a fill with no decision row is included unfiltered but never under any action. In the real engine both are unlikely (one decision per symbol per tick, written in the same transaction as the fills, one `now` per tick), so non-blocking; at least document it. Reversal returns both legs under `reverse` and only the close leg under `close` is not mixed, as intended. Note `_iso` (`web.py:92`) would raise (500) if a ts column held non-numeric text; the engine never writes that, non-blocking.
6. Memory (non-blocking). Each CSV is built fully in memory (rows as dicts, then a StringIO, then the response): a 7 MB decisions.csv (50k rows) took about 134 MB peak RSS in my test and 5 s, in a sync route so it runs in the threadpool and does not block the event loop. At about 600 decisions/day that is fine for a year or two; the existing HTML page already loads all trades. If it grows, switch to `StreamingResponse` with a generator and LIMIT-free keyset paging by id.
7. CSV injection (PASS, with notes, non-blocking). Tested payloads in reason, symbol, side, kind, signal, action (and fast/slow stored as text, since SQLite is typeless): `=1`, `+1`, `-1+cmd`, `@s`, tab, CR, LF prefixed, `=cmd|' /C calc'!A0` all come out with a leading `'`. Numeric detection is by Python type only (`web.py:67`), so a string such as `-1+cmd` or `-5` in a REAL column is a `str` and is prefixed; it is never treated as a number. Floats: NaN is stored by SQLite as NULL and written empty; `inf` and `-inf` are written as `inf` / `-inf` (Excel treats these as text, not formulas); negative floats stay numeric. Not neutralised: leading space or ideographic space then `=` (` =cmd`), full-width `＝`, `|`, `%`. These do not start a formula in Excel or LibreOffice (a leading space makes the cell text; `|` and `%` only matter after `=`), so this matches the brief's list; optionally also strip leading whitespace before the check as defence in depth. Expected quirk: a legitimate string that starts with `-`, such as a reason beginning `-`, gains a visible apostrophe in some viewers. CSV quoting round-trips with `csv.reader` (embedded quotes, tabs, CR/LF verified).
8. Secrets, auth, engine (PASS). Output columns are only DB columns plus UTC time columns; no config, env or path values appear; `/api/` routes get no new auth logic (Caddy covers them); `engine.py`, `db.py`, `uv.lock` untouched. HTML in the new card row is passed through `escape()` (verified with a `<b>` reason).
9. Report accuracy (non-blocking). The dev's reconciliation runs were done on hand-built DBs; my engine-driven reconciliation agrees. The report's "85 passed" matches what I see on head.
