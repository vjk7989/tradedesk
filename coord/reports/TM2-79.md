# TM2-79 report: security headers in Caddy (+ dash CSP)

## Summary
All three sites now import one shared `(security_headers)` snippet (HSTS, nosniff, no-referrer, Server removed).
mcp and dash also send `X-Frame-Options: DENY`. dash alone sends a strict Content-Security-Policy. The paper-bot dashboard
works under that policy: it has no inline JS, and its auto-refresh is a `<meta http-equiv="refresh">`. openalgo gets the
shared snippet only.

## Caddyfile change (deploy/Caddyfile, developer commit 7b1016db)
- New snippet `(security_headers)`: a `header { defer ... }` block with `Strict-Transport-Security "max-age=31536000"`
  (no `preload`, no `includeSubDomains`: the sslip.io deploys rotate), `X-Content-Type-Options "nosniff"`,
  `Referrer-Policy "no-referrer"`, `-Server`. `defer` applies these after the upstream response, so they override
  upstream values.
- `mcp.{$DOMAIN}`: `import security_headers` + deferred `X-Frame-Options "DENY"`. Routing is unchanged.
- `openalgo.{$DOMAIN}`: `import security_headers` only, plus a comment explaining why there is no XFO/CSP.
- `dash.{$DOMAIN}`: `import security_headers` + deferred `X-Frame-Options "DENY"` and
  `Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; frame-ancestors 'none'"`.
  basic_auth and reverse_proxy are unchanged.

## Dashboard and inline JS
paper-bot/paper_bot/web.py has no inline JS: no `<script>`, no `on*=` handlers and no `javascript:` URLs. It also loads
nothing from another origin: links are relative (`/api/*.csv`, `/?...`) and the filter is a same-origin GET form. Refresh is
`<meta http-equiv="refresh" content="30">`, which needs no script. Inline CSS (`<style>` and `style=` attributes) is covered
by `style-src 'unsafe-inline'`. The equity chart is inline `<svg>` markup, which is not an image fetch. `img-src data:` is
allowed for safety. No CSP or dashboard change was needed.

## openalgo decision
**Shared snippet only. No CSP and no X-Frame-Options.** OpenAlgo is a third-party UI. It may rely on inline scripts and
styles, and it may use frames. Any CSP or XFO we set could break it, and we can't test its pages here.
HSTS, nosniff, no-referrer and Server removal do not affect how it renders.

## Review
Verdict: **approved**. Notes:
- `Referrer-Policy: no-referrer` is safe for mcp. trade-mcp does no Referer/Origin checks, so dropping Referer cannot break
  the OAuth/login flow.
- trade-mcp's login page already sets its own XFO and `frame-ancestors`. The deferred `X-Frame-Options: DENY` matches
  that and does not conflict.

## Tests
New `deploy/test_tm2_79_headers.py` (19 tests). It reuses `test_pb2_edge.caddy_blocks`, `compose()` and `default_hash()`
rather than duplicating them. Header blocks are parsed into `{field: [values]}`, both the `header { }` form and the
one-line form.
- `test_snippet_exists_once`, `test_snippet_headers_exact`: the snippet has `defer` and exactly HSTS `max-age=31536000`,
  nosniff, no-referrer and `-Server`.
- `test_hsts_no_preload_or_subdomains`: no `preload`/`includeSubDomains` anywhere in the file, and every HSTS value is exact.
- `test_snippet_has_no_frame_or_csp_headers`: the snippet carries no XFO/CSP, because it also applies to openalgo.
- `test_site_set_is_exactly_three`: sites are derived from the file and must be exactly mcp/openalgo/dash. The only
  snippet is `(security_headers)`.
- `test_every_site_imports_snippet_once[site]` (x3): imported once, as the block's first directive.
  `test_all_derived_sites_import_snippet` checks that any site added later imports it too.
- `test_xfo_deny[mcp|dash]`: `X-Frame-Options DENY`, and every header block in those sites uses `defer`.
- `test_mcp_has_no_csp`, `test_openalgo_no_xfo_no_csp` (openalgo has no header block and no XFO/CSP/frame-ancestors in code).
- `test_dash_csp_exact`: directives parsed into a dict and compared, so whitespace does not matter.
  `test_dash_script_src_strict` checks there is no `'unsafe-inline'`/`'unsafe-eval'` in script-src or default-src.
  `test_dash_headers_exact` checks dash sets only XFO and CSP.
- `test_dashboard_source_is_csp_safe`: scans paper_bot/web.py. Within markup tags it checks for no `<script`, no `on*=`,
  no `javascript:`, no `//` or `http(s)://` src/href/action, and no `<iframe|object|embed|link>`. It also checks for no
  external `url()`, no `@import`, and that a meta refresh is present. This always runs.
- `test_rendered_dashboard_is_csp_safe`: renders `web.render()` in-process on an empty DB and on a DB with an open/close,
  equity points and a hostile decision reason (`<script>...` / `onclick=` / `javascript:`), then checks the same rules.
  It needs fastapi/httpx, which the deploy env lacks, so it skips there (`importorskip`). Run locally with
  `--with fastapi --with httpx`: it passes.
- `test_caddy_validate_with_headers`: `docker run <compose caddy image> caddy validate`, with the image read from
  docker-compose.yml. Env: DOMAIN/ACME_EMAIL/DASH_USER dummies and the compose fail-closed default bcrypt hash (the same
  pattern as the PB-2 validate test). It skips if docker is not installed or the daemon is down. Docker is absent here,
  so it was skipped locally and will run in the CI deploy job.
