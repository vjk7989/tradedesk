# TM2-64 report: sandbox.edge "50 sequential runs" memory checks

Phase 2: set the new bounds (owner approved 11:35 IST). Data from phase 1 and the CI samples is in `coord/reports/TM2-64-data.md`.

## Final design (`trade-mcp/test/sandbox.edge.test.ts`, describe "sandbox limits")

The `Δexternal < 8 MB` assertion is replaced by two checks. The rss, heapUsed, active-handles and degradation assertions are unchanged.

| check | definition | bound | healthy CI | healthy local | 1 MB/run leak |
|---|---|---|---|---|---|
| end external | `process.memoryUsage().external` after the final gc / sleep 20 ms / gc | ≤ 36 MB | 2.05 or 18.05 | 2.35 or 18.35 | 52.35 |
| slope | mean external of runs 26-50 minus mean of runs 1-25 | ≤ 12 MB | -6.0 .. +5.8 | -10.4 .. +6.9 | +13.0 .. +34.2 |

- The phase-1 instrumentation is gone: no `TM2-64-DATA` line, and no heapUsed/rss/arrayBuffers samples, gc timing or per-run series. Each run now records only `process.memoryUsage().external`, outside the timed region.
- The test keeps a gc every 5th run (10 calls; no gc after every run). The slope needs it: the CI bounds were calibrated with it, and without it the healthy slope widened locally to -24.9 .. +8.9 MB over 6 runs, close to the 12 MB bound. The leak's lowest slope also dropped to 16.8.
- Shared code: `fiftyRuns(perRun?)` does the warm-up, base, 50 checked and timed runs, and final gc. `externalChecks(series, endExternal)` returns `{endMB, slopeMB, endOk, slopeOk, ok, endMsg, slopeMsg}`, where `ok = endOk && slopeOk`. The real test asserts `ok === true`, and the leak proof asserts `ok === false`, so the two conditions come from one helper and cannot drift apart.
- A failure prints both actual values and both bounds, e.g. `end external 52.35 MB (bound 36 MB); external slope 21.03 MB, mean runs 26-50 minus runs 1-25 (bound 12 MB)`.

### Primary and secondary signal
- **End external is the primary leak signal.** A 1 MB/run leak gives 52.35 MB against the 36 MB bound, a 16 MB margin. Healthy runs end at 2.05 or 18.05 MB on CI (2.35 or 18.35 local), 18 MB under the bound.
- **Slope is the secondary signal.** It catches a gradual leak whose end value hasn't reached 36 MB yet. Its margin on the 1 MB/run leak is thin under load: the lowest leak slope seen was 13.02 against a bound of 12. So the leak proof does not assert it; the slope value and its pass/fail verdict appear only in the proof's messages.

## Leak proof (committed, runs in CI on every run)

New test `50 sequential runs: the external checks flag a simulated 1 MB/run leak`. It runs the same `fiftyRuns` loop, and after each run it pushes `Buffer.alloc(1 MB)` into a local array (+50 MB in total). It then asserts (a) `ok === false`, meaning the real test would fail, and (b) `endOk === false`. `slopeOk` is not asserted (coordinator change after the first push); the slope value and verdict appear in both assertion messages. The buffers are released in `finally` (`leak.length = 0`). The suite stays green while the proof runs every time.

The output was captured with a temporary stderr line, which was removed before the commit:

```
TM2-64-TMP leak endOk=false slopeOk=false end external 52.35 MB (bound 36 MB); external slope 18.48 MB, mean runs 26-50 minus runs 1-25 (bound 12 MB)
TM2-64-TMP leak endOk=false slopeOk=false end external 52.35 MB (bound 36 MB); external slope 21.03 MB, mean runs 26-50 minus runs 1-25 (bound 12 MB)
```

Both checks flagged the leak in all 153 leak runs of the first version, which still asserted the slope (Linux, Node v24.22.2):
- whole file alone ×10: end 52.35 every time; slope 18.48 .. 25.56
- whole file with a parallel full suite ×5: slope 13.02, 13.87, 18.50, 19.76, 30.04
- inside the parallel full suites ×5: slope 26.41 .. 31.01
- the leak test alone (`-t`) in a loop during 2 more full suites ×133: slope min 16.86, median 26.84, max 34.21

**Margin note:** the slope's lowest leak value was 13.02, only 1 MB above the bound, in a whole-file run under load. The leak adds exactly +25 MB of slope, and the 16 MB WASM steps add about -12 .. +9 MB of noise. That margin is why the proof asserts the combined verdict and the end check, but not the slope.
