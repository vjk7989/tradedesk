# TM2-44 report · de-flake OAuth rate-limit tests under load

Branch: tm2/TM2-44 (from main 9f00321). This is a test-only change, and production code is unchanged.

## Change
- `trade-mcp/test/oauth.edge.test.ts`, "exactly 5 failures allowed, 6th -> 429 with Retry-After": the per-test timeout is now **12_000 ms** (it was the 5 s default).
- `trade-mcp/test/tm13_oauth_persist.edge.test.ts`, "4 failures then restart: 5th attempt is still allowed": the per-test timeout is now **15_000 ms** (it was the 5 s default).
- The assertions are unchanged: 5 failures are allowed, the 6th gives 429 with `Retry-After: 900`, and the counts survive a restart (401 then 429). No skips were added.

## Seam decision: no seam, so the cost stays and the timeouts go up
`src/oauth/login.ts` `verifyPassword` calls `scryptSync(password, salt, expected.length)` with Node's default parameters (N=16384, r=8, p=1). The stored format `scrypt:<saltHex>:<hashHex>` (validated in `src/oauth/config.ts`) carries no cost parameters, and no config or env var sets them. A test can't choose a lower cost without changing production code, so the scrypt cost stays and only the timeouts change.

## Measurements
Method: a scratch clone with timing added (never committed) wrapped each `/login` call and each whole test body with `performance.now()`. Only the two target tests ran (`-t`). The machine has 8 cores and was already busy before any load was added: load average was 13 to 24 from other work.

| Condition | Metric | n | p50 | p99 | max |
|---|---|---|---|---|---|
| Alone (10 runs) | per attempt, rate-limit test | 60 | 200 ms | 444 ms | 517 ms |
| Alone | per attempt, restart test | 60 | 210 ms | 527 ms | 632 ms |
| Alone | whole test, rate-limit | 10 | 1410 ms | 2603 ms | 2603 ms |
| Alone | whole test, restart | 10 | 1877 ms | 3345 ms | 3345 ms |
| 2 parallel full suites (15 runs, load avg 24 to 31) | per attempt, rate-limit test | 90 | 208 ms | 772 ms | 829 ms |
| Loaded | per attempt, restart test | 90 | 272 ms | 935 ms | 1031 ms |
| Loaded | whole test, rate-limit | 15 | 1894 ms | 3978 ms | 3978 ms |
| Loaded | whole test, restart | 15 | 2187 ms | 5132 ms | **5132 ms** |

Under load the restart test hit 5.13 s, over the 5 s default, which reproduces the flake. The new timeouts are about 3× the loaded worst case: 3 × 3.98 s ≈ 12 s and 3 × 5.13 s ≈ 15 s. (With n = 10 to 15, p99 equals the max.)
