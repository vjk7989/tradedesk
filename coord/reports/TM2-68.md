## Choice: `format="ISO8601"`
Every source is ISO-8601. ISO8601 parses date and date-time strings per element (no first-string inference) and does not guess day/month order for ambiguous strings, whereas `"mixed"` would (verified: `"01/05/2024"` -> 2024-01-05 under `mixed`, NaT under `ISO8601`). Non-ISO input is therefore flagged by the warning rather than silently guessed. datetime64 (s/ns checked), object Timestamps and `None` still work.

Note (out of scope, not changed): `fundamentals_loader.py:105` (and 103-104) still use inferred `to_datetime(errors="coerce")` on raw SEC strings; SEC always emits `YYYY-MM-DD` so it is not currently lossy, but the same pattern could be hardened in a follow-up.
