# TM2-35 report: oauth:revoke-all operator command

## Changes
- `trade-mcp/src/oauth/revoke-cli.ts` (new): CLI. Refuses without `--force` (exit 2, explains the single-process rule). Missing store: nothing to do, no file created. Corrupt store: refuses (exit 1), file untouched, so registered clients are never wiped. Prints counts and fixed text only.
- `trade-mcp/src/oauth/provider.ts`: `revokeAll()` only. Clears access, refresh, rotated, codes and pending, then calls the existing `persist()` (tmp file + rename, 0600). Clients and loginFailures are untouched. Returns counts.
- `trade-mcp/package.json`: script `oauth:revoke-all`.
- `trade-mcp/test/tm2_35_revoke_all.test.ts` (new, 3 tests): end-to-end through the real HTTP server and a restart. Old access gives 401, old refresh and outstanding code give 400, the static MCP_TOKEN still works, a fresh login on the same client works. Clients and rate-limit state are identical before and after. The output is grepped for every issued token, code, rid, stored hash, password hash and MCP_TOKEN. Also covers refuse-without-force, missing store and corrupt store.

## Runbook line
Leaked connector token: `cd trade-mcp && docker compose stop trade-mcp && DATA_DIR=<dir> npm run oauth:revoke-all -- --force && docker compose start trade-mcp` (or, if the container is running, `docker compose exec trade-mcp npm run oauth:revoke-all -- --force` then restart trade-mcp straight away so the live process drops its in-memory copy). Then rotate MCP_TOKEN in .env separately (static tokens are not affected).
