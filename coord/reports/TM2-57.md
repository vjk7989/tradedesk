## Reproduction

The test failed in 2 of the 6 loaded full-suite runs in that session (both in load clones, run 2). TM2-52's two earlier failures had the same signature:

```
FAIL  tm2_46_datadir_lock.edge.test.ts > real trade-mcp process > SIGKILLed server seen from another hostname ...
AssertionError: expected null to be +0
 ❯ test/tm2_46_datadir_lock.edge.test.ts:905:35
    904|     c.p.kill("SIGTERM");
```

So the failing step was **not** the 15 s window. The refused start and the CLI passed every time: diagnostics showed b exits in 2.9-3.9 s under load and sees "heartbeat 4s ago", well inside the window. What failed was the final graceful SIGTERM. Server c exited with code `null` / signal `SIGTERM`, which means the default action killed it.

## Root cause
`src/index.ts` prints `trade-mcp started ...` and only then runs `process.on("SIGTERM", stop)`. The test sent SIGTERM as soon as it saw the started line (25 ms poll, then one `readLock`). Under load the child can be descheduled between its `write()` of that line and the `process.on` call. If so, SIGTERM hits Node's built-in handler, which resets stdio and re-raises with the default action. The process dies by the signal and the lock is not removed.
- Probe (scratch, not committed): send SIGTERM the instant the started line arrives. **14 of 15** servers died by SIGTERM.
- The same probe, gated on "the SIGTERM listener is installed": **15 of 15** exited 0.
- The other real-process test in this file does more work between "started" and its signal, so it rarely hits the window. It has the same latent race (SIGINT to `d` right after `portOpen`). It is out of scope here and was not changed.

## Change (test only)
- **SIGTERM only after the handler exists.** `startServer(dir, port, { sigtermReady: true })` is opt-in and is used only for server c in this test. It adds a child preload (`--import data:text/javascript,...`) that observes and does not change behaviour. On `newListener("SIGTERM")` it prints `[tm2-57] SIGTERM listener installed` from a microtask, which runs after `main()`'s synchronous tail, so the handler is in place by then. `started` then also requires that marker after the started line. /proc `SigCgt` cannot be used because Node catches SIGTERM from startup.
- **Heartbeat ages pinned, with no elapsed-time dependence:**
  - **In-process edge checks with `checkLock`:** `LIVE_WINDOW_MS - 5 s` → live, `now - 1 s` → live, and `now - (LIVE_WINDOW_MS + 5 s)` → stale.
  - **Real refused start and real CLI:** both run inside `whileFresh()`, which sets the mtime to now − 1 s and re-sets it every 100 ms until the child exits. Whenever the child reads the lock, after however long tsx startup takes, it sees a fresh heartbeat. The CLI is now an async `spawn`, because `spawnSync` would block the pinning timer.
  - **Real replacing start:** the mtime is set to now − 20 s and asserted stale in-process first. After that nothing touches it: a is dead and the pin timer is cleared synchronously, so it only gets older.
- **Truly dead first:** after SIGKILL the test awaits the `exit` event, asserts `{code: null, signal: "SIGKILL"}`, and asserts that `process.kill(pid, 0)` throws. A's heartbeat timer cannot touch the mtime after that.
- **Intent kept and assertions tightened:**
  - refused start exits 1 with "already running … crashed-container-1 … wait up to 15s", prints no "started", and does not bind the port; the lock is unchanged;
  - CLI exits 4 with the "trade-mcp is running (lock heartbeat Ns ago)" message, and `oauth.json` is unchanged;
  - the stale lock is replaced ("replacing stale … crashed-container-1"), the new lock belongs to c, and the port is bound;
  - SIGTERM gives exit 0, the lock is removed, and nothing is left over;
  - no secrets appear in any output.
- **Timeout and gating:** the per-test timeout is now 240 s (it was 90 s file-wide), for 4 tsx starts under load. `skipIf(IS_WIN)` is unchanged. Linux is not skipped.
