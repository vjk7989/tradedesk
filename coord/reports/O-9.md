# O-9 report: sandbox hardening follow-ups

Files: `trade-mcp/src/sandbox/quickjs.ts`, new `trade-mcp/test/o9_sandbox_hardening.test.ts`. No existing test edited.

## Changes
1. **Fail closed on removed globals.** After the deletes, a guest-side check lists any removed name still not `undefined` on `globalThis`. If any, the run fails with `sandbox init failed` before user code runs.
2. **In-guest argument sizing.** A guest `JSON.stringify(arg).length` wrapper runs first, under the guest memory limit. Above 1 MB (or unserializable, or guest OOM) it rejects with `binding argument too large` and no host `vm.dump` or `JSON.stringify` happens. The host check stays as the second check.
3. **Result cap.** Before `newString`, a stringified result longer than `min(4 MB, memoryBytes/4)` rejects the guest promise with `binding result too large (N chars, max M): narrow the query, e.g. fewer bars or a shorter date range`.
4. **Leaks.** `jsonParse` (and the new size-wrapper handle) are disposed before the context. `disposeQuietly` now disposes the runtime in a `finally`, so it runs even if `vm.dispose()` throws.
5. **Heap ceiling.** Kept at memoryBytes + **16 MB** (brief said 32 MB). It is documented in a code comment: it covers the runtime overhead plus string marshalling at the largest allowed payloads, and it is the tighter bound. The ceiling is now also checked when a binding settles (resolve and reject handlers) and in `pump`, so before the guest resumes, not only in the interrupt handler.

## Result cap chosen
Default **4 MB** of JSON characters, or `memoryBytes/4` if smaller (the 64 MB default memory gives 4 MB).

## Realistic payload size
A year of daily bars (252 rows of `{timestamp, open, high, low, close, volume, oi}`) is about **27 KB** of JSON (~107 bytes/bar). That is about 0.7% of the cap. A year of 5-minute bars (~18.9k rows, ~2 MB) also fits at the default 64 MB memory.

**Can hit the cap:** 1-minute bars over a long range (~94k bars a year, ~10 MB), or 5-minute bars over multi-year ranges. Those return `binding result too large` and the AI is told to narrow the query. Note that with small `memoryBytes` (e.g. 8 MB) the cap is 2 MB (~19k bars).

## Tests (15, all in the new file)
Fail-closed (init-delete suppressed via a pass-through module mock), in-guest sizing (host fn never called, no >1 MB host stringify), result cap (4 MB, memoryBytes/4, year of bars fits), dispose (clean vm/runtime dispose, runtime disposed when vm.dispose throws), settle-time ceiling (fake wasm size), and a 200-run mixed hostile/normal loop. Stated tolerance: RSS +64 MB, external +32 MB after GC. 8 of them fail against the old code.
