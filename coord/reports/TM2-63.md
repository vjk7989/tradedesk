### BLOCKING: the signal window still covers acquireLock()
Node installs a native SIGINT/SIGTERM handler (SignalExit) at startup. Until a JS listener exists, that handler kills the process synchronously, even while JS is running. It does not defer the signal to the event loop. Because stop is registered only after acquireLock() returns, a signal during acquireLock (after its "replacing stale" log, or between linkSync and `process.on`) kills the process by signal. The review's item 1 assumed signals are only dispatched at the await, which is wrong for this case.
- Probe: dist, a dead-pid stale lock seeded, SIGTERM at the first stderr line, 30 runs. 29/30 exited `null/SIGTERM`. Each failed run left `trade-mcp.lock.<pid>.<rand>.tmp` and `trade-mcp.lock.replace`. That replace guard blocks the next start for up to 10 s.
- Same probe with an empty DATA_DIR: 30/30 exit 0. The first line there is "started", so the race is not hit.
- Fix verified on a scratch dist copy: move `process.on("SIGINT"/"SIGTERM", stop)` (with stop and its lets) to before `acquireLock()`; `process.on("exit", releaseLock)` stays right after it. Result: 10/10 stale-seeded and 10/10 empty, all exit 0, no files left. A signal that lands during acquireLock is then deferred until main's synchronous run ends, by which point the exit hook is installed. The probe edit was deleted; src is not touched. Once fixed, (d) should keep `acquireLock(` after the registration. The (d) assertion `reg > lock` will then need flipping. That is a test change I will make with the src fix.

## Fix round 1

Finding: SIGINT/SIGTERM `stop` was registered only after `acquireLock()`, so a signal during it (e.g. while replacing a stale lock) hit Node's default disposition and left `trade-mcp.lock.<pid>.<rand>.tmp` / `trade-mcp.lock.replace` behind.

Change (trade-mcp/src/index.ts only): the `stopping` / `heartbeatStop` / `http` lets, `stop`, and `process.on("SIGINT"|"SIGTERM", stop)` now come BEFORE `acquireLock()`. `process.on("exit", releaseLock)` stays immediately after `acquireLock()` with no await between. `stop` is safe in every phase (heartbeatStop/http optional; exits at once unless http is listening; idempotent via `stopping`). Log text and stdio mode unchanged; no POSIX-only code.

Sync check: `datadir-lock.ts` has no async/await/Promise; `acquireLock` is fully synchronous, so handler registration -> acquireLock -> exit-hook registration contain no await or async boundary. A signal is delivered on the event loop only afterwards, `stop` calls process.exit(0), and the exit hook releases the lock. No leak path remains. (Tmp/replace files are created and removed inside the sync call.)

Results: tsc --noEmit and build clean; tm2_63_shutdown_order + tm2_46 edge: 72 passed, 1 skipped, 0 failed (source-order test (d) also passed as run here); full vitest: 77 files, 2529 passed, 5 skipped; e2e/smoke.mjs: ALL PASS.
Probe: 20 runs, stale lock seeded, SIGTERM at first stderr line: 20/20 exit 0, no lock, no .tmp, no .replace.
