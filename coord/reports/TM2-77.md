## Safety design
1. Default `EXECUTION=sim`: the openalgo module is not imported, OPENALGO_* / CONTRACT_SIZES are not even parsed in sim.
2. Startup (`Engine.__init__`, runs in the app lifespan): `analyzer` status must return `data.analyze_mode` as a real boolean `true`. OFF, HTTP error, timeout, non-JSON, missing/odd shape all raise `RuntimeError("... refused to start ...")` and the app does not start.
3. Before EVERY order (`OpenAlgoExec.place`): analyzer re-checked. Off or error: nothing is sent; decision row `skip` with "openalgo analyzer off: order refused" (or "analyzer check failed (...): order refused").
4. Order is MARKET, sent at most once, never retried. Outcomes:
   - success with non-empty `orderid`: recorded.
   - definite reject (JSON `status:"error"` on HTTP 4xx, or 2xx with `status:"error"`; or connect refused so the request was never delivered): `skip` row with the reason; no position change.
   - anything else (timeout, 5xx, non-JSON, success without orderid, network error): outcome UNKNOWN. Decision `skip`, and state key `openalgo_unknown:<SYMBOL>` halts further orders for that symbol until an operator reconciles in OpenAlgo and deletes that state row. (This is the TM2-73 never-retry posture; a duplicate order is worse than a missed one.)
   - an exception after an order was sent (e.g. DB error rolling back the rows) also sets the halt key, so the rolled-back candle cannot re-send.
5. Reverse = two independent orders, each gated. If the close is refused nothing opens. If the close succeeds and the open fails, the decision is `close` with the open failure in the reason.
6. Key: only held in `OpenAlgoExec._key` and the Config field (`repr=False`); sent only in the request body. Audit: logs use exception type names or fixed text, never `str(httpx exception)`; all response text and orderid pass through `_redact` and are truncated; Config validation errors never include the key; `OpenAlgoExec.__repr__` is fixed; the dashboard renders a fixed field list (no config dump); nothing key-related is written to the DB (the fake-run scan below confirms).
7. `follow_redirects=False`: a redirect is a non-success and so an error.
8. Residual risk (cannot be closed from the client side): analyzer toggled between the re-check and the order (milliseconds). Timeouts are per-phase httpx timeouts, not a hard total deadline.

## Quantity, fills, schema
- Contracts = floor(units / size) (round DOWN, tolerance 1e-9, so it never exceeds NOTIONAL_USD). 0 contracts: refused, `skip` row ("notional ... is below one contract"). Close sends round(position qty / size), where the stored position qty is exactly contracts x size.
- Fill and P&L: the analyzer reply has no fill price, so entry/exit are modelled exactly as sim does (last closed candle close, plus SLIPPAGE and TAKER_FEE) and every decision reason says "fill modelled from candle close". Nothing claims the analyzer filled at that price.
- Schema is unchanged (no `orderid` column; db.py not touched). The order id is recorded in the decisions `reason` text and in `state` as `openalgo_order:<id>` = "SYMBOL SIDE contracts". A trades.orderid column would need a db.py change, left as a follow-up for the owner.

## Review
Verdict: APPROVE (no blocking findings). Reviewer: independent adversarial pass at head 170355f. `uv run pytest -q`: 199 passed.

Findings
1. NON-BLOCKING (fix recommended) openalgo_exec.py `_call` (msg line): `str(j.get("message"))[:120]` is truncated BEFORE `_redact`, so a server message that echoes the key across the 120-char cut leaks a key prefix into the decision reason (DB/dashboard). Reproduced (10+ chars of key in reason). Fix: redact, then truncate. Needs a server that echoes the key, and only a prefix leaks. orderid path redacts before truncating (OK).
2. NON-BLOCKING crash window (engine.py `_ox_order`/`_txn`): the order is sent inside the open DB transaction. A hard kill, power loss or BaseException (CancelledError/KeyboardInterrupt are not caught by `except Exception` in `_write`) after the send but before COMMIT rolls back last_candle and the halt key, so the restart would re-send for that candle. Residual duplicate risk, paper/sandbox only. Mitigation: commit the halt key (`openalgo_unknown:<SYM>` = "sending") before the POST and clear it after the rows commit.
3. NON-BLOCKING mode switch (engine.py `_act_ox`): a position opened under sim (qty = notional/price, not a multiple of the contract size) and then run with EXECUTION=openalgo closes with floor(qty/size) contracts; if that is 0, `place` returns REFUSED ("invalid order") every candle, and the position is stuck. Also OpenAlgo has no such position. Operator procedure: do not flip an existing sim DB to openalgo; use a fresh DATA_DIR. Worth a line in the owner docs.
4. NON-BLOCKING (owner verification) Symbol suffix `FUT` (config.py `openalgo_symbol_suffix`, source trade-mcp api-docs.ts:10, which itself says "confirm with market.search"). Owner must confirm BTCUSDFUT (or the real master-contract name) against OpenAlgo before turning this on; a wrong symbol is rejected (4xx) or lands as unknown, never live because analyzer-gated.
5. NON-BLOCKING: operator reconcile procedure exists only as the reason text and this report ("delete state key openalgo_unknown:<SYM>"). No exact SQL (`DELETE FROM state WHERE key='openalgo_unknown:BTCUSD'`) or "check OpenAlgo orderbook/positions first, then flatten local position row if needed" runbook. Add to owner docs.
6. NON-BLOCKING: `place(..., contracts=True)` passes the bool-is-int check (quantity true). Engine never passes a bool. Harden with `type(contracts) is int`.
7. INFO: the API key travels in the JSON body (mirrors client.ts:63-66); with an http:// OPENALGO_URL it is plaintext on the wire. Acceptable for an internal compose service; use https otherwise. Sync httpx runs inside `asyncio.to_thread` (OK, not on the event loop), but holds the BEGIN IMMEDIATE write lock for up to 2 x timeout per symbol; dashboard readers are separate RO connections.
8. INFO sim vs openalgo divergence: P&L/fills in `trades` are modelled from the candle close with slippage and fee (as sim), not the sandbox's fills; qty = contracts x size (so rounded down vs sim). Every decision reason says "fill modelled from candle close" and has the order id; no schema change, so the TM2-72/76 dashboards render the same column set and action vocabulary (open/close/reverse/skip/hold). A reverse whose open leg fails shows as action `close` with the failure in the reason. No mis-render seen.

## Fix round 1
Source: config.py untouched this round; engine.py and openalgo_exec.py changed. No tests.

1. **Key prefix leak.** `OpenAlgoExec.redact` removes the key and every >= 8-char prefix or suffix of it (longest first), and now runs BEFORE any truncation (`redact(msg)[:120]`). `place()` applies a final redaction to every Result reason; the engine redacts again in the decision writer (`decide`). orderid already redacted before truncating. Log lines use fixed text or exception type names only. Fragments shorter than 8 chars are not redacted (accepted).
2. **Crash window.** Sequence in `Engine._ox_order`: COMMIT work so far, then in its own committed transaction write `state` key `openalgo_inflight:<SYM>` = "candle <ts> <side> <contracts>", then open a new transaction and POST. The result rows and the marker delete are written in the transaction the outer `_txn` commits (marker cleared right after `_close`/`_open`, or in the refused/rejected/unknown path). The halt check (`openalgo_unknown` OR `openalgo_inflight`) runs at startup (warning per symbol), at the top of `_act_ox`, and again inside `_ox_order` before each leg. `BaseException` (KeyboardInterrupt, CancelledError) around the send and result region rolls back, commits `openalgo_unknown`, and re-raises; `_txn` rollback is now tolerant of an already-closed transaction.
   Crash-point analysis:
   - Kill before the marker commit: no POST happened, nothing was sent; restart re-evaluates the candle normally (the mid-act COMMIT may already have saved last_candle, then the candle is skipped as already processed, which is safe).
   - Kill after the marker commit, before/during the POST: the marker is durable, so restart halts the symbol (the order may or may not exist; operator reconciles).
   - Kill after the POST, before the result commit: the same marker is durable, so halt; no resend.
   - Kill after the result commit: the rows and the marker delete committed together; the order is recorded and last_candle is set, so no resend.
   A hard kill can therefore only produce a halt, never a second order. The cost is that a mid-act COMMIT happens before each order (a reverse's close leg is now durable before the open leg is sent).
3. **Sim to openalgo on one DB.** Startup refuses if any open position's qty is not a whole, >= 1, multiple of its CONTRACT_SIZES entry (or has no size). Use a fresh DATA_DIR when switching to openalgo.
4. **Operator procedure** (exact text is also in the skip reason). For each halted symbol: (1) check the OpenAlgo orderbook and positions for the symbol; (2) reconcile manually if needed, e.g. fix or delete the local `positions` row to match; (3) run `sqlite3 <DATA_DIR>/paper.db "DELETE FROM state WHERE key IN ('openalgo_unknown:<SYM>','openalgo_inflight:<SYM>');"` (table `state`, columns `key`, `value`); (4) no restart is needed: the markers are read on every tick.
5. `place` rejects bools (`type(contracts) is int`).
6. **Transport note for the owner:** the API key travels in the JSON body (as trade-mcp does), so OPENALGO_URL must be the in-network compose address or https; never plain http over the internet. Add to the compose env lines: `OPENALGO_URL=<in-network compose address or https URL; never http over the internet>`.
