# TM2-67 report: tz-aware price index in tushare fundamentals merge

## Change
`bt-service/vibe_bt/backtest/loaders/tushare_fundamentals.py` (only file edited): in `enrich_price_frames_with_fundamentals` the internal merge key `_trade_date` is built from the index; if the index is tz-aware it is `tz_convert("Asia/Shanghai")`, `tz_localize(None)`, then `.normalize().as_unit("ns")`. Naive indexes take the same path as before (normalize, as_unit ns). `merged.index = original_index` already restored the caller's index, so output index (tz, unit, values) is unchanged. `subdaily="next_day"` shifts the PIT date by one day against the CN-local date key, so UTC 2024-02-29 23:30Z (03-01 07:30 CST) sees the 03-01 rule.

## Reasoning
PIT dates are naive CN-local dates; tz-aware bar keys made merge_asof raise MergeError. Converting to CN-local wall-clock date is the correct comparable key.

1. 2. (non-blocking, verified) tz-aware UTC and Asia/Shanghai in s/ms/us/ns: output index `.equals` and dtype-equal to the input; values equal the equivalent naive CN-local index.
3. (non-blocking, verified, critical point) PIT, ann_date 2024-02-29, `next_day`, UTC bars 02-29 00:00Z / 15:59Z / 16:00Z / 23:30Z / 03-01 00:00Z give [nan, nan, 42, 42, 42]. The fundamental appears exactly at 16:00Z (= CN 03-01 00:00) and not at 15:59Z, so no early visibility. The Shanghai-tz control gives [nan, nan, nan, nan, 42]. The 23:30Z bar sees 42 as the brief requires. An unsorted tz index keeps its order. Under `reject`, any non-midnight UTC bars raise SubdailyPitError, so they are never enriched there. CN offset is >= UTC, so the CN date is never earlier than the UTC date; any key error would delay visibility, not advance it.
4. (non-blocking) `_is_subdaily_index` (tushare_fundamentals.py:277-309) judging tz-aware indexes on their own wall clock is sound. Midnight-only distinct-day bars in any tz shift by a constant offset and keep distinct CN dates, so the daily verdict and the key agree. Any bar with a non-midnight local time is subdaily, which is the conservative direction (e.g. UTC 16:00 daily bars are rejected). Remaining edge: a tz-aware frame whose own wall clock is all-midnight but spans a UTC offset change (DST) could collide on CN dates only if two bars share a CN day, which needs sub-day spacing and therefore a non-midnight stamp. Not reachable. Optional hardening: judge on the CN-local clock; not required.
5. (non-blocking, verified) No new warnings: probes ran with warnings as errors on pandas 3.1.1. `uv run pytest -q tests/test_tm2_60_datetime_columns.py tests/test_tm11_*.py` and the tushare-related files: 189 passed, 1 failed (the expected strict XPASS, test_tushare_enrich_tz_aware_index_not_supported at tests/test_tm2_60_datetime_columns.py:131-137).
