# O-16 report: EXECUTE_MEMORY_MB

## Done
- `trade-mcp/src/config.ts`: `EXECUTE_MEMORY_MB` -> `executeMemoryBytes`. Same parsing as EXECUTE_TIMEOUT_MS (trim, `^-?\d+$`, else default), clamped to [16, 512] MB, default 64.
- `trade-mcp/src/server.ts`: `runCode(..., { memoryBytes: deps.executeMemoryBytes ?? deps.cfg.executeMemoryBytes ?? 64*1024*1024, timeoutMs })`.
- `deploy/docker-compose.yml`: `EXECUTE_MEMORY_MB: ${EXECUTE_MEMORY_MB:-64}`. `deploy/.env.example`: var with a sizing comment (EXECUTE_MAX_CONCURRENT, TRADE_MCP_MEM_LIMIT; the name TM2-47 used is `TRADE_MCP_MEM_LIMIT`).
- `trade-mcp/test/o16_execute_memory.test.ts` (new, 13 tests): 16, 512, 15, 513, -1 (clamps to 16, like -1 for timeout -> 5000), abc, 1.5, empty, whitespace, unset; a real execute run with 16 fails a 30 MB retained allocation ("memory limit exceeded"), the same run passes at 64.

## YAGNI exception
The brief says `deps.executeMemoryBytes`, but `index.ts` (not in the 5 files) builds deps without it, so the setting would never reach production. server.ts therefore falls back to `deps.cfg.executeMemoryBytes` (the same way executeMaxConcurrent is read). `deps.executeMemoryBytes` is kept as an override. No index.ts change needed.

## Runbook (owner adds after merge)
- Set `EXECUTE_MEMORY_MB` in `deploy/.env` (16-512, default 64) and `docker compose up -d trade-mcp`.
- Sizing: trade-mcp worst case = base (~100 MB) + EXECUTE_MAX_CONCURRENT x (EXECUTE_MEMORY_MB + 32 MB WASM + pending binding bytes, ADR-18/19) must stay under TRADE_MCP_MEM_LIMIT. Example at 128 MB x 4: 100 + 4 x (128+32+128) = 1252 MB, so set TRADE_MCP_MEM_LIMIT=1536m.

## Troubleshooting
- Execute error "memory limit exceeded": the script retained more than EXECUTE_MEMORY_MB. Retain less (stream, trim arrays) or raise EXECUTE_MEMORY_MB and check TRADE_MCP_MEM_LIMIT.
- trade-mcp container restarting / OOM-killed (exit 137): EXECUTE_MAX_CONCURRENT x (EXECUTE_MEMORY_MB + ~160 MB) exceeds TRADE_MCP_MEM_LIMIT; lower one or raise the other.
- Value ignored: non-integers (abc, 1.5) fall back to 64; out-of-range integers are clamped to 16..512.
