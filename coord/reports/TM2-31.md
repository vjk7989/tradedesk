# TM2-31 report: walk-forward over india_options and composite baskets

Result: tests only. `bt-service/bt_service/walkforward.py` is unchanged; no test exposed a real bug in it.

## What was added
- `bt-service/tests/test_tm2_31_wf_options.py` (real runner, local fixtures, all walk-forwards run once and concurrently in a module-scoped fixture; about 50 s).
- Fixtures `tm2_31_ce_1d.csv` (NIFTY25NOV24000CE, 2025-10-27..2025-11-25, last bar is the expiry bar; premium falls 300 to 244 by 11-03, climbs to 360, settles at 352.33), `tm2_31_und_1d.csv` (index, close = 24005 + premium, consistent with the premium), `tm2_31_eq_1d.csv` (equity, uptrend).
- Setup: train 20 / test 5 days, start 2025-10-27, end 2025-11-26, metric total_return, two candidates (w=0.3, w=0.1). Two folds; fold 2 tests [11-21, 11-26), which contains the 11-25 expiry.

## Findings
- Selection discriminates: CE-only fold 1 trains on a falling premium and picks w=0.1; fold 2 trains on a rising one and picks w=0.3. Params and test metrics are asserted exactly; fold 2 equity is rescaled to start where fold 1 ended.
- Expiry: fold 2's test run on its own reproduces the fold's metrics (nothing carried from fold 1); its trades are a buy and a sell with reason `expiry` on 11-25, so the expiry settles inside the fold where it falls.
- Look-ahead (perturbation tests): bars after fold 1's train cutoff scaled x1.5 leave fold 1's chosen params and train_score unchanged; bars after fold 2's cutoff scaled x0.4 leave fold 2's chosen params and train_score unchanged (fold 1 untouched).
- Composites asserted exactly: CE+equity, and CE+equity+underlying (the latter also covers settlement at intrinsic against the mapped underlying; fold 1 picks 0.1, fold 2 picks 0.3). The mapped-underlying-only test was dropped.
- Thin and empty data: a train window with 5 option bars runs and scores with no warning (pinned). A fold with zero option data returns `ok: false` with a fold-numbered error. A fold after expiry (fold 1 of a single-candidate run tests [11-26, 12-01)) returns `ok: false` with `fold N: test run failed ... missing symbol`. No crash.
- Fixture trap, not a bug: an underlying inconsistent with the premium gave a fake +80% at expiry, because settlement uses intrinsic against the mapped underlying.

## Known gaps, deliberately not changed
- Thin (not empty) data gives no warning; only an empty fold errors. Tracked as TM2-39.
- A failed fold's result drops completed folds (`ok: false` without `folds`), unlike the budget path. Pinned by `test_walkforward.py:130` and `test_walkforward_edge.py:520`. Tracked as TM2-38.
- Both are pinned in the new tests with comments, so a future change must update them.
