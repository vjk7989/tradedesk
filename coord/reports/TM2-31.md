# TM2-31 report: walk-forward over india_options and composite baskets

Result: tests only. `bt-service/bt_service/walkforward.py` is unchanged; no test exposed a real bug in it.

## What was added
- `bt-service/tests/test_tm2_31_wf_options.py` (8 tests, real runner, local fixtures, about 5.5 min).
- Fixtures `tm2_31_ce_1d.csv` (NIFTY25NOV24000CE, 2025-10-27..2025-11-25, last bar is the expiry bar), `tm2_31_und_1d.csv` (index, consistent with the premium), `tm2_31_eq_1d.csv` (equity).
- Setup: train 20 / test 5 days, start 2025-10-27, end 2025-11-26, metric total_return, three candidates (weight 0.1, 0.3, -0.2). Two folds; fold 2 tests [11-21, 11-26), which contains the 11-25 expiry.

## Findings
- (a) Single CE: both folds choose w=0.3; metrics asserted exactly. Fold 2's test run in isolation reproduces the fold's metrics (nothing carried from fold 1), and its trades are a buy on 11-24 and a sell on 11-25 with reason `expiry`, so the expiry settles inside the fold where it falls. Test windows chain with no gap or overlap; train never overlaps test; oos equity has no train dates.
- (b) Composites asserted exactly: CE+equity, CE+underlying (mapped), CE+equity+underlying. Options legs are lot-sized and settle on expiry in the composite.
- (c) Few bars: a train window with only 5 option bars runs and is scored (no warning is emitted). A fold with zero option data returns `ok: false` with `fold 0: no candidate produced a finite total_return: ... missing: [...]`. A third fold after expiry returns `ok: false` with `fold 2: test run failed ... missing: [...]`. No crash or traceback.
- A fixture trap, not a bug: an underlying inconsistent with the premium gave a fake +80% return at expiry, because settlement uses intrinsic value against the mapped underlying. The underlying fixture is now built consistent with the premium.

## Gaps noted but deliberately not changed
- Thin data (not empty) gives no warning; only an empty fold gives an error. The brief's "clear warning" is met only as a clear error.
- A failed test run discards completed folds (`ok: false` without `folds`), unlike the budget path. This is pinned by existing tests (`test_walkforward.py:130`, `test_walkforward_edge.py:520`), so it is left alone.
- If either is wanted, it is a separate behaviour-change task.
