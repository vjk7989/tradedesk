# TM2-71 report: de-flake server.edge CLI spawn tests

Branch `tm2/TM2-71`. Changed file: `trade-mcp/test/server.edge.test.ts` (test only).

## Measurement (Linux, 8 vCPU; there is no Windows host here, so nothing was measured on Windows)

I added temporary `performance.now()` timing around the two `spawnSync` calls, logged to a file, and removed it before committing.

| Scenario | n spawns | p50 | p99 | max |
|---|---|---|---|---|
| File alone, 10 runs | 20 | 486 ms | 912 ms | 912 ms |
| File under load, 10 runs (2 full `npx vitest run` suites in parallel, restarted as they finish, load avg 17–24) | 20 | 1427 ms | 4657 ms | 4657 ms |

Split by test under load: `--help` p50 1952 / max 4463 ms; missing-config p50 1232 / max 4657 ms.
With n=20, p99 is the maximum sample. A loaded spawn at about 4.7 s leaves almost no room under vitest's 5 s default, which matches the flakes seen in the merge tests. One full suite takes about 180 s alone.

## Fix

- `CLI_TEST_TIMEOUT_MS = 20_000`: the vitest timeout for both tests. This is about 4× the loaded p99 of 4.7 s, at the low end of the brief's 20–30 s range. It goes above 3× because the merge-test machines that flaked were probably more loaded than this one.
- `CLI_SPAWN_TIMEOUT_MS = 15_000`: the spawnSync `timeout`, with `killSignal: "SIGKILL"`. SIGKILL means a CLI that ignores SIGTERM cannot keep spawnSync blocked. The 5 s gap means spawnSync kills a hung CLI before vitest's timeout fires.
- A shared `runCli()` helper throws `CLI did not exit within 15000 ms (hung?); signal=SIGKILL` when `error.code === "ETIMEDOUT"` or `r.signal` is set. The message does not include stdout or stderr, because those can contain the secrets these tests check for.
- The assertions are unchanged: `status` is 0 and stdout contains `trade-mcp` for `--help`; for missing config, `status` is not 0 and stdout+stderr do not contain the API key.
- Side benefit: before this change, the missing-config test already had `timeout: 10000`. A hung CLI there was killed with `status === null`, and `expect(null).not.toBe(0)` passed. So a hang in that test was a false pass. It now fails with the message above.

### Other spawnSync calls in the file
- `:432` `beforeAll` runs `tsc -p tsconfig.json` only when `dist` is missing. It has an explicit 60 s hook timeout and is a build step, not a CLI-under-test spawn, so it is not the same pattern and is unchanged.
- The `--stdio` test uses async `spawn` with its own 15 s wait helper and a 30 s test timeout. It is not spawnSync and is unchanged.
- Other test files spawn too (tm2_35, tm2_46, tm2_49, tm2_63), but they are outside this task's scope and were not changed.

## Hang proof (local only, not committed, reverted)

I temporarily pointed `runCli` at a script that never exits (`setInterval(() => {}, 1 << 30)`):
- With the spawn timeout temporarily set to 1 s, both tests failed in about 1.0 s with `Error: CLI did not exit within 1000 ms (hung?); signal=SIGKILL`.
- With the committed constants (15 s / 20 s), both failed in 15.0 s with `Error: CLI did not exit within 15000 ms (hung?); signal=SIGKILL`. Neither run produced a vitest "Test timed out".
- No sleeping process was left behind. The file was restored, and only the intended diff remains.
