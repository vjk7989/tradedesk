# TM2-74 report: agent-runner interval schedules (everyMinutes)

## Design
- `Schedule` gains optional `everyMinutes` and `between`; `time` becomes optional. Exactly one of `time`/`everyMinutes` (parse error naming the job otherwise).
- `nextRun` dispatches to `nextIntervalRun` for interval schedules; the `time` path is untouched.
- Files changed: `agent-runner/src/jobs.ts`, `src/scheduler.ts`, `src/main.ts` (only the `schedule:` line of `--dry-run`, which printed `schedule.time`), README. Run loop = `runScheduler` in scheduler.ts (main.ts only wires it).
- Tests not edited. jobs.gemini-paper.example.json NOT changed (the brief does not ask for it, and tm2_73_gemini_paper_job.test.ts asserts a `time` schedule). README text for the cron workaround now says it is the pre-TM2-74 alternative.

## Edge-case decisions
- everyMinutes: integer 5..1440; 0, 4, 1441, 7.5 rejected. 1440 gives one slot per day at 00:00.
- Grid is local minute-of-day k*N, restarting each local day; if N does not divide 1440 the last gap is shorter (N=7: 23:55 then 00:00).
- `days` filters by local weekday of the slot.
- `between`: both ends inclusive, start < end required (no overnight wrap, start==end rejected), HH:MM only. Does not re-anchor the grid (45 min in 09:15-15:30 gives 09:45...). Rejected with `time`.
- IST fixed +05:30, UTC; no DST, so no DST handling (confirmed: Mar/Oct DST-date start instants are in the identity run, results identical).
- Overlap: the scheduler is a single sequential loop, so runs can never actually stack. After a run finishes, interval slots that fell in (due, finish] are logged per slot as `job <name>: slot <ISO> skipped (previous run still active)`, then the next due is the first grid slot after the finish time (absolute grid, so later slots do not shift). Only interval jobs log this; `time` jobs behave exactly as before. Note a slot delayed only by ANOTHER job running is run late, not skipped (existing behaviour).
