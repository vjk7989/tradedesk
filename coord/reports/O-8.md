# O-8 report
Approach (src/sandbox/quickjs.ts):
1. Deleted `SharedArrayBuffer`, `DataView`, `Atomics`, `WebAssembly` from the context globals before user code runs (bindings return JSON, so no typed array reaches the guest another way).
2. Hard ceiling on WASM linear memory via `QuickJS.getWasmMemory()` (experimental accessor in quickjs-emscripten 0.32). Ceiling = size after context creation + memoryBytes + 1 MB. Checked in the interrupt handler and once more after the run (memory never shrinks, so short runs that finish between interrupt checks are still caught). Error: `memory limit exceeded`; it wins over the timeout text.

Deviations from the brief (AC wins):
- `ArrayBuffer` and the TypedArray constructors are NOT removed. The PR #57 REPORT test requires `new Uint8Array(1<<20)` x16 to succeed at 64 MB, and the pinned test "memory cap stops allocation... next run is clean" requires a 1 MB Uint8Array at 4 MB. Removing them would break both; I may not edit tests. The ceiling covers them instead (REPORT test passes).
- Headroom is 1 MB, not 32 MB: the 16 MB initial heap has ~9 MB free, so 16 x 1 MB only grows memory by ~7 MB; a 32 MB headroom could not fail the REPORT case.
- Pinned tests that broke: none (globalThis-keys test is a subset check).
Risk: ceiling is baseline-relative and coarse; a single huge allocation is only seen at the next check.

## Fix round 1 (owner ruling)
ArrayBuffer and all TypedArray constructors are now deleted too (a single `new ArrayBuffer(2**31)` grows WASM before any check). Heap ceiling is now absolute: memoryBytes + 16 MB. Expected failures, both use Uint8Array (now ReferenceError): sandbox.edge "REPORT: control pair (Uint8Array)" (64 MB run must succeed) and "memory cap stops allocation... next run is clean" (final `new Uint8Array(1<<20)`). Test writer to update.

## Fix round 2
Binding calls now cap: argument JSON size 1 MB ("binding argument too large"), in-flight calls 64 (the existing 20-concurrent test needs >16; "too many pending binding calls"), pending arg bytes <= memoryBytes. Rejections happen in the guest before the host copy is kept; slots/bytes are freed on settle. The "detached ArrayBuffer" error did not reproduce after the caps; cause not isolated (likely WASM growth under flood).
