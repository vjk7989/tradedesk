## What to build
Windows editors often save JSON with a UTF-8 BOM. Today both readers reject it.
- Strip one leading `﻿` before `JSON.parse`, in both places, through one tiny shared helper (e.g. export `stripBom` from config.ts, imported by lint.ts).
- Nothing else changes: invalid JSON is still rejected, and a BOM in the middle of the file is still an error.

## Acceptance criteria
- A BOM file loads in both readers and gives the same result as the file without a BOM.
- Only one BOM is stripped. A double BOM is rejected.
- A UTF-16 BOM file is still rejected, with a clear error.
- Existing tests stay green.
