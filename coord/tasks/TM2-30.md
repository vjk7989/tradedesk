## What to build
`node dist/main.js --jobs jobs.json --dry-run <name>` prints, for that job:
- the backend;
- the model, if one is configured or a default applies;
- the MCP url;
- the token env **name** and whether it is `set` or `missing`;
- the timeout;
- the schedule and next run (job tz and UTC);
- the resolved prompt text, verbatim.

It exits 0 and spawns nothing. It makes no network call.

## Acceptance criteria
- No secret value is printed, including when the prompt text contains an env var's value.
- An unknown job name exits 1 and lists the valid names.
- `--dry-run` combined with `--once`, `--check` or `--next` gives a clear error.
- A spy proves that no spawn or fetch happens.
- Existing tests stay green and unedited.
