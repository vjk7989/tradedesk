# TM2-35 · trade-mcp · emergency `oauth:revoke-all` operator command
Branch: tm2/TM2-35        Base: main        Owner: TM2

## Why
If a connector token leaks, the operator needs one command that kills every OAuth access token, refresh token and pending code at once. Today the only options are to wait for expiry or to delete `oauth.json` by hand while the server is stopped.

## Files you may touch
- `trade-mcp/src/oauth/revoke-cli.ts` (new): CLI entry.
- `trade-mcp/src/oauth/provider.ts`: add `revokeAll()` only. It clears every token/code/pending/rotated map and persists. Don't change any other method.
- `trade-mcp/package.json`: one script, `"oauth:revoke-all"`.
- `trade-mcp/test/tm2_35_revoke_all.test.ts` (new)

## What to build
- `node dist/src/oauth/revoke-cli.js` loads the OAuth store from `DATA_DIR`, calls `revokeAll()`, and prints only counts (`revoked N access, M refresh, K codes`), never a token.
- Registered clients (DCR) stay registered, so users only log in again.
- The login rate-limit state is kept.
- The single-process rule applies: the CLI refuses to run, and says so, unless `--force`. Document it this way: stop trade-mcp, run the CLI, start trade-mcp, or use `docker compose exec` with `--force`. Put the runbook line in your report.
- Static `MCP_TOKEN` and `MCP_TOKEN_READONLY` are unaffected. Say this in the output: "rotate MCP_TOKEN in .env separately".

## Acceptance criteria
- After `revokeAll` and a restart, old access and refresh tokens give 401, and a fresh OAuth login works.
- Clients and rate-limit state survive.
- The output never contains a token or a hash. The test greps the output for every token issued in the test.
- Existing OAuth tests stay green and unedited.

## Verify
`cd trade-mcp && npm ci && npx vitest run && npx tsc --noEmit && npm run build`
