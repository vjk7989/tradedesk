# TM2-68 · bt-service · explicit `filed` parsing in _ffill_pit, warn on drops
Branch: tm2/TM2-68        Base: main        Owner: TM2        Approved: owner 10:17 IST

## Finding (TM2-60 follow-up 2)
`bt-service/vibe_bt/backtest/loaders/fundamentals_loader.py:185` runs `pd.to_datetime(sparse["filed"], errors="coerce")`. pandas infers one format from the first string, so mixed formats (`"2024-01-03"` next to `"2024-01-04 16:30"`) silently become NaT. They are then dropped at line 187, and the fundamentals data loses rows without any signal.

## Files you may touch
- `fundamentals_loader.py`. Your test writer adds `bt-service/tests/test_tm2_68_ffill_pit_formats.py`.

## What to do
- Parse explicitly: `format="ISO8601"` if every source emits ISO-8601, else `format="mixed"`. Find out which sources feed `filed` and state the choice with evidence. Keep the datetime64 and Timestamp inputs that TM2-60 tested working.
- If any non-null `filed` value fails to parse, log one `warnings.warn` (or the module's logger, matching existing convention) that gives the count and up to 3 example raw values. Don't raise, keep `errors="coerce"` semantics, and never log data values beyond those examples.
- Behaviour for all-ISO-date input must be byte-identical to main.

## Acceptance criteria

- A truly unparseable value is dropped *with* exactly one warning carrying the count.
- No warning when everything parses.
- There is a pre-fix failure proof.
- The full suite is green and has no new warnings.
