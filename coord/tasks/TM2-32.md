# TM2-32 · trade-mcp · search: rank Rules lines by tokens matched
Branch: tm2/TM2-32        Base: main        Owner: TM2
Owner approval: chat 2026-11-28 ("TM2-32 search ranking … approved").

## Why
TM2-25 prepends the first 8 API_HEADER lines that match any token, in header order. A broad token can fill the cap and push out the line the caller wants. For example, the query "e maxShortOptionQtyPerOrder" drops the cap line, which is the 9th header line.

## Files you may touch
- `trade-mcp/src/sdk/search.ts`: the Rules selection only.
- `trade-mcp/test/tm2_32_search_rank.test.ts` (new)

## What to build
- For each header line, score = the number of **distinct** query tokens it contains (case-insensitive substring, as today). Lines with score 0 are excluded.
- Select the top `MAX_RULES` (8) lines by score descending; ties go to the earlier header line.
- **Output the selected lines in header order**, so the block still reads like the header.
- Change nothing else: entries matching, the 20-entry cap, the readonly filter, the empty-query path, the "No API entries match" message and the block format all stay the same.

## Acceptance criteria
- "e maxShortOptionQtyPerOrder" includes the cap line.
- When ≤8 header lines match, the output is byte-identical to TM2-25's.
- Queries with no header match are byte-identical to today.
- Readonly still renders no trade.* entry.
- Pinned TM2-25 tests that freeze "the first 8 matching lines" for >8-match queries are updated by your test writer (an AC change); all others stay green and unedited.
