# O-16 · trade-mcp + deploy · EXECUTE_MEMORY_MB (per-run sandbox memory is configurable)
Branch: own/O-16        Base: main        Owner: OWNER

## Why
TM2-54 found that the per-run sandbox memory is fixed at 64 MB (quickjs.ts default) with no setting. The operator sizes the VPS with EXECUTE_MAX_CONCURRENT and the container mem_limit (TM2-47), and needs this third knob. Worst case for trade-mcp ≈ base + N × (memoryBytes + 32 MB), per ADR-19.

## Files you may touch
- `trade-mcp/src/config.ts`: add `EXECUTE_MEMORY_MB` → `executeMemoryBytes`. Integer MB, clamped to [16, 512], default 64. Copy the EXECUTE_TIMEOUT_MS parsing style exactly.
- `trade-mcp/src/server.ts`: pass `memoryBytes: deps.executeMemoryBytes ?? 64*1024*1024` to `runCode` (line ~69).
- `trade-mcp/test/o16_execute_memory.test.ts` (new)
- `deploy/docker-compose.yml`: the trade-mcp env `EXECUTE_MEMORY_MB: ${EXECUTE_MEMORY_MB:-64}`.
- `deploy/.env.example`: the var, with a sizing comment that references EXECUTE_MAX_CONCURRENT and TRADE_MCP_MEM_LIMIT (check the exact variable name that TM2-47 used in compose).

Put the runbook and troubleshooting lines in your report. The owner adds them after merge. The API_HEADER (O-14) documents the *default* 64 MB; add a note in the report about whether its doc test should now read the default from config.

## Acceptance criteria
- Env parsing: unset gives 64. Test 16, 512, 15, 513, -1, `abc`, `1.5`, empty and whitespace; each must match the EXECUTE_TIMEOUT_MS behaviour for the analogous input.
- A real run with EXECUTE_MEMORY_MB=16 fails a 30 MB retained allocation with "memory limit exceeded". The same allocation passes at 64.
- The compose default resolves to 64.
- Existing tests stay green. Pinned config key-set and compose key-set tests may need the test writer; list them.

## Verify
`cd trade-mcp && npm ci && npx vitest run && npx tsc --noEmit && npm run build`, `uv run --with pytest --with pyyaml pytest -q deploy/`, plus CI.
