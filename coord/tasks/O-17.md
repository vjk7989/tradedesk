# O-17 · trade-mcp · risk: run static checks BEFORE any broker/quote call
Branch: own/O-17        Base: main        Owner: OWNER        Priority: HIGH (safety ordering)

## Finding (first real Claude CLI session on the GCP deploy, 2026-11-28)
A MARKET BUY of 500 BTCUSDFUT on CRYPTO (maxQtyPerOrder=100) was not refused by the risk engine. It reached the OpenAlgo call and failed with `HTTP 403: Invalid openalgo apikey`, so nothing was placed. The likely cause: the order path fetches a price quote from the broker for the notional check *before* it runs the cheap, deterministic checks.

## Files you may touch
- `trade-mcp/src/risk/engine.ts`, and/or the order path in `trade-mcp/src/sdk/bindings.ts` (trade.place/modify only)
- `trade-mcp/test/o17_static_checks_first.test.ts` (new)

## What to build
1. Before ANY network call (quote, analyzer status, place), run every check that needs no market data:
   - kill switch, mode/analyzer requirement;
   - market hours and holidays;
   - allowedExchanges, allowedProducts, symbolAllow/Deny;
   - maxQtyPerOrder, maxShortOptionQtyPerOrder;
   - maxOrdersPerDay, maxOrdersPerRun.

   Any failure gives the existing `risk denied: ...` text, with no broker call.
2. Only then fetch the quote and run the notional checks (per-order, USD, per-day, daily loss).
3. Keep the reserve/commit/release semantics and the audit entries unchanged. A refused order must be audited as refused, not as an error.

## Acceptance criteria
- A spy client proves an over-qty order, a disallowed exchange, a disallowed product, the kill switch and a closed market each make **zero** client calls and return the exact existing denial text.
- A valid-size order still fetches the quote and runs the notional checks.
- The existing risk/order tests stay green. If a pinned test asserts the old call order, list it for the test writer.

## Verify
`cd trade-mcp && npm ci && npx vitest run && npx tsc --noEmit && npm run build`, plus CI.
