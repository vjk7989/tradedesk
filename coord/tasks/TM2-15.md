# TM2-15 · trade-mcp · let /readyz really cancel the OpenAlgo probe
Branch: tm2/TM2-15        Base: main (latest)        Owner: TM2

From the TM2-10 review (LOW): `/readyz` races `client.analyzerStatus()` against a 3 s timer. The OpenAlgo request itself keeps running until the client's own 10 s timeout, because `analyzerStatus()` takes no signal.

## Files you may touch
- `trade-mcp/src/openalgo/client.ts`: an optional `signal?: AbortSignal` on `analyzerStatus()`, threaded into `call()` and combined with the client's own timeout controller. No other method changes behaviour.
- `trade-mcp/src/http.ts`: `/readyz` `checkOpenalgo` only.
- `trade-mcp/test/tm2_15_readyz_cancel.test.ts` (new)

## Build
- `call(endpoint, body, signal?)`: abort the request when either the caller's signal or the internal timeout fires. Error mapping and redaction stay the same. Other public methods are unchanged: they pass no signal.
- `/readyz`: create an `AbortController`. When the existing 3 s `setTimeout` fires, abort it and pass its signal to `analyzerStatus(signal)`. Keep `setTimeout`, not `AbortSignal.timeout`: the existing TM2-5 fake-timer edge tests drive this deadline, and they must stay green unedited.

## Acceptance criteria
- After the 3 s readyz deadline, the fake fetch used by the OpenAlgo client sees `signal.aborted === true`.
- Existing client tests, readyz tests and edge tests stay green, unedited.
- No change to the order paths.
