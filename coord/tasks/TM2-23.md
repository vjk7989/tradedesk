# TM2-23 · trade-mcp · optional risk cap on short option lots (NFO/BFO CE/PE sells)
Branch: tm2/TM2-23        Base: main        Owner: TM2

## Why
`orderNotional` for NFO is qty × premium. A short option sells cheap premium but carries risk on the underlying, so the existing notional caps barely limit short options. Add an **optional, off-by-default** cap.

## Files you may touch
- `trade-mcp/src/config.ts`: add only `maxShortOptionQtyPerOrder: posInt.optional()` to `riskSchema`.
- `trade-mcp/src/risk/engine.ts`: the check.
- `trade-mcp/test/tm2_23_short_option_cap.test.ts` (new)
- `deploy/risk.example.json`: don't add the key (it stays off by default). Mention it in the report instead.

## What to build
- When the key is set and an order is a SELL of an option symbol (`...CE` or `...PE` on NFO or BFO, using the same symbol rule as the bt routing, or a simple suffix check), refuse if `quantity > maxShortOptionQtyPerOrder`.
- Refuse with `risk denied: short option qty <q> exceeds maxShortOptionQtyPerOrder <n>`, following the existing reason style.
- BUY orders, FUT, equities and CRYPTO are unaffected.
- The check doesn't know whether a SELL closes a long position, which is conservative. Document that in the report.

## Acceptance criteria
- Off by default: no behaviour change without the key.
- Cases: a CE/PE SELL over the limit is refused; at the limit it is allowed; a BUY over the limit is allowed; FUT is unaffected; lowercase symbols and the exchange are normalised the same way as elsewhere.
- `risk:lint` and `loadConfig` accept the new key.
- Pin the clock in the tests (`RiskEngine` `now`).
- Existing tests stay green and unedited, except pinned schema key-set tests. Those are updated by your test writer, which is an AC change.
