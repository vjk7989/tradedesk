# TM2-77 · paper-bot · optional execution through OpenAlgo's sandbox (analyzer) instead of local simulation
Branch: tm2/TM2-77        Base: main        Owner: TM2

## Why
Today paper-bot simulates fills locally from Delta public candles. Once the owner adds Delta keys to OpenAlgo, paper trades should go through OpenAlgo's **Analyzer (sandbox) mode**, so the same broker plumbing is exercised before going live. It must stay paper-only.

## Files you may touch
- `paper-bot/` engine/config plus a new `paper-bot/.../openalgo_exec.py`, at most 4 source files.
- `paper-bot/tests/test_tm2_77_openalgo_exec.py` (new)
- Put the compose env lines in your report. The owner wires deploy.

## What to build
- `EXECUTION=sim|openalgo`, default `sim`, so behaviour is unchanged.
- In `openalgo` mode:
  - at startup, check that OpenAlgo's analyzer status is ON. If it isn't, refuse to start with a clear error; **never place a live order**;
  - place orders through the OpenAlgo REST API (`OPENALGO_URL`, plus `OPENALGO_API_KEY` from env, never logged);
  - record the returned order id and fill (or the rejection reason) in the trades and decisions tables;
  - re-check analyzer status before every order, failing closed.
- Use the OpenAlgo API shapes that trade-mcp's client already uses (`trade-mcp/src/openalgo/client.ts`). Mirror them; don't guess.
- Quantities in contracts: use the Delta lot/contract sizes the user configures (`CONTRACT_SIZES=BTCUSD:0.001,...`). Refuse symbols without a size.

## Acceptance criteria
- A fake OpenAlgo covers:
  - analyzer off gives refuse-to-start;
  - analyzer turning off mid-run gives the order refused and a skip row;
  - place success and rejection;
  - a timeout;
  - the API key never appears in logs, the DB or the dashboard.
- `sim` mode is byte-identical to today (existing tests unedited and green).
