# TM2-59 · bt-service · explicit-unit assertions in pass-through tests
Branch: tm2/TM2-59        Base: main        Owner: TM2
Owner approval: chat 2026-11-28 08:47 IST, item 3.

## Why
The TM2-43 test writer found tests that pass under pandas 3 only because some paths keep the input unit (`us`), or because both sides of a comparison share it. If ns normalisation is ever extended to those paths, or regresses, these tests would change behaviour silently.

## Files you may touch (tests only; your **test writer** edits them)
- `bt-service/tests/test_tm15_warnings_edge.py` (`_expected()` used by `test_resample_irregular_gaps` and `test_resample_single_row`)
- `bt-service/tests/test_p93_anchor_edge.py` and `bt-service/tests/test_p93_anchor.py`
- `bt-service/tests/test_intervals_edge.py`
- `bt-service/tests/test_tm11_edge.py` (`test_tushare_next_day_shift_matches_old`)
- `bt-service/tests/test_tm2_17_broker_time_edge.py` (`_assert_same`)

## What to build
- In each, make the unit expectation explicit:
  - for paths that resample, assert `out.index.unit == "ns"`;
  - for documented pass-through or refuse paths, assert that the unit equals the input's unit (and say why in a comment);
  - build expectations in the unit you assert.
- Don't change source. Values and intent are unchanged.

## Acceptance criteria
- The full suite is green on pandas 3.1.1. Every test listed has an explicit unit assertion.
- A one-line note per test in the report: why that unit is expected.
