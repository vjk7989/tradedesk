## What to build
- `node dist/main.js --jobs jobs.json --check`:
  - validates the file with `parseJobs`;
  - checks each job's `mcp.tokenEnv` is set, printing only `set` / `missing`, never the value;
  - checks the backend's key env is set, by name only: `ANTHROPIC_API_KEY` for `api`, `OPENAI_API_KEY` for `api-openai`, `GEMINI_API_KEY` for `api-gemini`, and nothing for the CLI backends;
  - prints a table and exits 0 if all are OK, 1 otherwise.
- `node dist/main.js --jobs jobs.json --next [N]`:
  - prints the next N (default 5) run times per job, in the job's tz and in UTC;
  - uses `nextRun`;
  - runs nothing.

## Acceptance criteria
- Never prints secret values.
- Invalid jobs exit 1 with the parse error.
- `--next` with N = 0, negative or non-numeric gives a clear error.
- `--next` output is correct across a weekend and the IST midnight boundary (fake clock).
- Existing `--help` / `--once` / scheduler behaviour is unchanged.
- Existing tests stay green.
