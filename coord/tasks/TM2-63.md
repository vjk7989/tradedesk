# TM2-63 · trade-mcp · register shutdown handlers before startup completes
Branch: tm2/TM2-63        Base: main (after #96 TM2-57)        Owner: TM2 (TM2 follow-up per TM2_SOLO §0)

## Why
TM2-57 found that `src/index.ts` logs `trade-mcp started` and only THEN registers `process.on("SIGINT"/"SIGTERM", stop)`. A SIGTERM or SIGINT anywhere between `acquireLock()` and those lines kills the process with Node's default action: exit by signal, `stop()` not run, heartbeat not stopped, and `exit` hook behaviour depends on the signal. The DATA_DIR lock is then left behind, and the next start waits out the 15 s live window or is refused. This happens in production with a `docker compose stop` or restart right after start. TM2-57 worked around it in the test with an observing preload (`sigtermReady`). The "second instance refuses …" test has the same latent race (SIGINT to server d).

## Files you may touch
- `trade-mcp/src/index.ts`: startup and shutdown only.
- `trade-mcp/test/tm2_61_shutdown_order.test.ts` (new) and the tm2_46 edge test (remove the now-unneeded `sigtermReady` preload and fix the "second instance" SIGINT race). Your **test writer** edits the tests.

## What to build
- Register SIGINT and SIGTERM handlers immediately after `acquireLock()` and before the heartbeat, `createHttpServer` and `listen`.
- `stop()` must be safe in every phase:
  - before listen: stop the heartbeat, release the lock, exit 0;
  - during listen: the same, without throwing if the server isn't listening;
  - after listen: today's behaviour, close plus `closeAllConnections`, then exit 0.
  - It is idempotent: a second signal is a no-op or an immediate exit 0, never a crash.
- Keep the `trade-mcp started …` log text exactly. stdio mode is unchanged.

## Acceptance criteria
- With a real process, a SIGTERM sent the instant the process is spawned, and again at the first stderr line, gives exit code 0 (not null) and removes the lock. Loop 20× under load.
- Existing tests are green. The TM2-57 preload is removed and the test still passes 20/20 under load. "Second instance refuses …" is fixed the same way.
- Windows: no POSIX-only assumptions in src.
