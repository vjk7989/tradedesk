## What to build
A short guide for anyone developing on the repo. Take every version and command from the repo files (package.json engines, `.python-version`/pyproject, the Dockerfile uv pin, ci.yml):
- Toolchain: Node 22, Python 3.12, uv 0.9.26 for lockfiles (the bt-service/README rule), Docker for the deploy tests.
- Per-package verify commands, the same as CI. e2e smoke: build first, then run `node e2e/smoke.mjs`.
- The test rules (ADR-17):
  - developers never edit existing tests; only the test writer updates pinned tests;
  - NSE-order tests pin the clock;
  - POSIX-only tests use `skipIf(win32)` with a reason.
- The PR flow: a branch per task, report in `coord/reports`, CI must be green, merge with `--match-head-commit`.
- Windows notes: no `TZ=Asia/Kolkata` in Git Bash; CRLF warnings are harmless.
- Security: never commit secrets; link SECURITY.md.
