## What to build
A symptom → cause → fix guide built from the code. Grep the real error codes and messages, and quote them exactly. At least these sections:
1. **Orders refused by risk:** every reason code from `trade-mcp/src/risk/engine.ts` and `hours.ts`, what triggers it, and the `risk.json` field or env var that changes it. Cover the kill switch, market hours, holidays, the caps, and audit fail-closed.
2. **OpenAlgo and the broker:** an expired daily session, a missing or wrong `OPENALGO_API_KEY`, a static-IP rejection, Analyzer (paper) vs live.
3. **MCP clients:**
   - 401: a wrong token, or the read-only token used for orders;
   - the OAuth redirect host is not allowed;
   - `EXECUTE_TIMEOUT_MS`;
   - the sandbox limits.
4. **Backtests:** bt-service errors for an unknown interval or symbol, too little data, and a walk-forward window that is too small.
5. **agent-runner:**
   - a CLI not logged in;
   - a missing API key env;
   - a bad `jobs.json` (point to `--check` from TM2-8, marked "planned" if not merged yet).
6. **Where to look:**
   - `docker compose logs`;
   - the audit JSONL location;
   - `/healthz` (and `/readyz` once #17 has merged).

## Rules
- Every error string you quote must exist in the code. List `file:line` for each one in your report, not in the doc.
- No secrets and no real hostnames: use `<DOMAIN>`.
- At most ~250 lines, and easy to scan. Tables are fine.

## Verify
Each quoted string can be found with grep. The owner's Sonnet reviewer will check every one.
