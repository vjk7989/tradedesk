# TM2-76 · paper-bot · bounded storage for a long-running VM
Branch: tm2/TM2-76        Base: main        Owner: TM2

## Why
paper-bot runs indefinitely on the VPS. Decisions (one row per symbol per 5 m), equity snapshots and logs grow without bound, and the dashboard queries the whole table.

## Files you may touch
- The paper-bot db and stats modules, at most 2 source files.
- `paper-bot/tests/test_tm2_76_retention.py` (new)

## What to build
- Indexes on (symbol, ts) and (action, ts) if they're missing, so the dashboard filters and CSV export stay fast.
- Equity snapshots older than `EQUITY_DETAIL_DAYS` (default 30) are downsampled to 1 per hour. Keep the first and last point per hour, so drawdown stays exactly correct; prove this.
- Decisions are **never deleted**, because they're the audit trail. Only add pagination (`?before=<id>&limit=`) to the API and dashboard.
- Run a startup `PRAGMA optimize` and a daily `VACUUM`-free maintenance step.

## Acceptance criteria
- With 1 year of synthetic 5 m data:
  - the dashboard and API respond in under 300 ms;
  - downsampling preserves max drawdown and final equity exactly;
  - the decision count is unchanged.
- Existing paper-bot tests stay green.

## Verify
`cd paper-bot && uvx --from uv==0.9.26 uv sync && uv run pytest -q`
