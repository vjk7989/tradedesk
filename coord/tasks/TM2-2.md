## Context (read only these)

- ADR-9 in `architecture-record-document.md`: an audit write must fail closed for orders. Today that is a writability probe before placing. Keep `appendAudit`'s signature and error behaviour: throwing on an unwritable file must still throw.

## What to build
Daily plus size-based rotation inside `appendAudit`:
- Before appending, if the existing file's last-modified **IST date** differs from today's IST date, or its size is ≥ `AUDIT_MAX_BYTES` (default 50 MB), rename it to `<name>.<YYYY-MM-DD>[.<n>].jsonl`, where n increments when that name already exists.
- After rotating, delete rotated files older than `AUDIT_RETENTION_DAYS` (default 90). Never delete the active file. Never delete files that don't match the rotation pattern.
- Do it synchronously, like the existing code, so ordering stays the same.

## Acceptance criteria
- No line is lost or duplicated across a rotation, including 1000 appends that cross the size limit.
- Rotation at the IST date boundary is exact: 18:29:59.999Z vs 18:30Z. Use an injectable clock: an optional third parameter `now?: () => Date` defaulting to `() => new Date()`. That changes no call site.
- Unknown or invalid env values fall back to the defaults.
- Retention deletes only matching rotated files older than N days, at the exact day boundary.
- An unwritable directory still throws, so the fail-closed order path is preserved.
- Windows paths work.
- All existing tests stay green: `npx vitest run`.
