# TM2-73 · agent-runner · example scheduled paper-trading job driven by Gemini
Branch: tm2/TM2-73        Base: main        Owner: TM2

## Why
The owner asked whether a Google (Gemini) API key can drive trading. agent-runner already supports `api-gemini` (TM2-3). Ship a ready, safe example and docs.

## Files you may touch
- `agent-runner/jobs.example.json`: add ONE example job, `paper-crypto-gemini`.
- `agent-runner/README.md`: a short "Gemini paper-trading job" section.
- `docs/connect-clients.md`: one line linking to it.

## What to build
- **The job:**
  - backend `api-gemini`;
  - schedule every 30 min in the UTC tz (crypto);
  - MCP url `https://mcp.<DOMAIN>/mcp` with `tokenEnv` pointing at the **full** token. Note in the docs: it needs `MCP_TOKEN`, not the read-only token, because it places paper orders.
- **The prompt:**
  - read `risk.status`, pull recent BTCUSD candles, decide with a simple stated rule, and place at most 1 paper order of qty ≤ 1;
  - always report its reasoning;
  - never retry a denied order.
- **Docs:**
  - `GEMINI_API_KEY`, the default model (quote it from the code), `--check` / `--dry-run` / `--next` usage, cost notes;
  - paper mode only: risk limits are enforced server-side, whatever the model decides.

## Acceptance criteria

- Every flag and env name greps exactly against the code.
- Existing tests stay green.
