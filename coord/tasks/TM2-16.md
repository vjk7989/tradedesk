# TM2-16 · bt-service · accept lowercase "1h" interval consistently
Branch: tm2/TM2-16        Base: main (latest)        Owner: TM2

Found by the TM-15 edge tests: `run_backtest(..., interval="1h")` is rejected as "unsupported interval", while the local loader's `_RESAMPLE_RULES` lists both `1h` and `1H`.

## Files you may touch (≤3)
- the bt-service module that validates `interval` before a run: find where "unsupported interval" is raised in `bt_service/`.
- `bt-service/tests/test_tm2_16_interval_case.py` (new)

## Build
Decide one rule and apply it at the validation point:
- Preferred: treat interval names case-insensitively where unambiguous (`1h` == `1H`, `1d` == `1D`), mapping to the existing canonical form. `m` (minute) must not be confused with `M` (month): check whether `M` is a supported interval anywhere first.
- If the canonical list is intentionally case-sensitive, reject `1h` consistently in the loader too, and document it.
Every interval currently accepted must stay accepted, with identical behaviour.

## Acceptance criteria
- `run_backtest` with `1h` behaves exactly like `1H` (same bars and metrics on a fixture).
- No currently accepted interval changes behaviour.
- Ambiguous cases are documented in the test.
