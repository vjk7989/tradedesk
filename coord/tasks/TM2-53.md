# TM2-53 · e2e · smoke covers the concurrency cap and memory recovery end-to-end
Branch: tm2/TM2-53        Base: main        Owner: TM2

## Why
O-10 (EXECUTE_MAX_CONCURRENT) and ADR-18/19 (sandbox memory) are unit-tested, but never checked through the real MCP HTTP path of a running server.

## Files you may touch
- `e2e/smoke.mjs`
- `e2e/README.md`

## What to build
Add 2 steps:
1. **Concurrency cap.** Start trade-mcp in smoke with `EXECUTE_MAX_CONCURRENT=2`, then fire 5 concurrent `execute` calls that each sleep about 1 s (await a resolved promise in a loop until a deadline, using no binary buffers). Assert:
   - exactly 2 or more succeed and the rest return the exact busy text from `src/server.ts`;
   - a follow-up call after they finish succeeds.
2. **Memory recovery.** Run one `execute` that exceeds memory, for example by retaining large arrays of strings. Assert:
   - `ok:false` with `/memory limit exceeded/`;
   - an immediate next `execute` (`return 1+1`) returns 2;
   - `/healthz` still answers.

## Acceptance criteria
- `node e2e/smoke.mjs` passes with the step count +2.
- Each step fails when its assertion is inverted. Prove this once and record it in the report.

## Verify
Build trade-mcp, then run `node e2e/smoke.mjs`.
