# TM2-27 · trade-mcp · risk.status reports every configured limit, including the optional ones
Branch: tm2/TM2-27        Base: main        Owner: TM2

## Why
`risk.status()` returns `limits: object`. The AI should be able to see every active cap before it places an order, including the optional `maxShortOptionQtyPerOrder` and `marketHolidays` counts, so it can plan within the limits instead of hitting denials.

## Files you may touch
- `trade-mcp/src/risk/engine.ts`: the `status()` method only.
- `trade-mcp/test/tm2_27_risk_status.test.ts` (new)
- (Put the api-docs signature/doc change in your report. The owner applies it, because api-docs.ts is owner-side right now.)

## What to build
- `status().limits` includes every riskSchema key with its effective value.
- Optional keys that are unset appear as `null`, not omitted, so the AI sees that they exist.
- `marketHolidays` is summarised as `{NSE: <count>, MCX: <count>, nextNSE: "<date>|null"}`, not the full lists.
- `contractValues` is summarised as a count.
- Add `today.remainingOrders` and `today.remainingNotional`.
- Never include any env value or secret.

## Acceptance criteria
- Every schema key is present in the output (the test iterates `riskSchema.shape`).
- Unset optional keys are `null`.
- The summaries are correct with a pinned clock.
- Existing `risk.status` tests stay green. If they freeze the exact shape, your test writer updates them (an AC change).
