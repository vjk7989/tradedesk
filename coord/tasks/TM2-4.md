## Context
- `trade-mcp` risk config key `marketHolidays` (merged in TM-3): `{ "NSE": ["YYYY-MM-DD", …], "MCX": [...] }`, with strict keys `NSE` and `MCX` only and real dates only. See `trade-mcp/src/config.ts` (the `marketHolidays` schema) and `deploy/risk.example.json`.
- OpenAlgo exposes `POST /api/v1/market/holidays` (API key in the JSON body). Docs: `vendor/openalgo/docs/api/market-calendar/holidays.md` in the owner's checkout, or online at docs.openalgo.in. Read the exact request and response fields there.

## What to build
`python deploy/sync_holidays.py --risk deploy/risk.json [--year 2027] [--dry-run]`:
- Reads `OPENALGO_URL` and `OPENALGO_API_KEY` from the environment. Never prints the key.
- Fetches holidays and maps them to the groups:
  - full closures of NSE, BSE, NFO, BFO or CDS go to `NSE`;
  - MCX closures go to `MCX`.
  - **Partial sessions** (e.g. MCX evening open on an NSE holiday, or a Muhurat session) are **not** full closures, so they are not added. Document this.
- Merges with the existing `marketHolidays`: union, sorted, de-duplicated. Every other key in `risk.json` is kept byte-for-byte as before. Re-serialise with the same indent and keep key order.
- Writes atomically (temp file + rename) and keeps a `.bak`.
- `--dry-run` prints only the dates that would be added (dates are public data).
- Exit codes: non-zero on HTTP error, `status != success` or malformed dates, and `risk.json` is left unchanged in that case.

## Acceptance criteria
- Tests use a local fake HTTP server (`http.server` in a thread), with no real network.
- Cover:
  - mapping and merge;
  - idempotency: running it twice gives no change;
  - that the output parses under the same rules as trade-mcp: only `NSE`/`MCX` keys, valid `YYYY-MM-DD`;
  - failure leaves the file untouched;
  - the API key is never in stdout or stderr;
  - Windows paths.
