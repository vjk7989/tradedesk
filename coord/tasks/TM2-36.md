## What to build
`node dist/main.js --jobs jobs.json --history [N]` (default 20, range 1..200) reads `<outputDir>/<job>/<date>[-n].md` (see jobs.ts:96-132) and prints the last N runs across all jobs, newest first, one line each:
- job name;
- the date and the `-n` suffix;
- the status (ok, failed or refused, parsed from the report header the runner writes; read jobs.ts for the exact format);
- the duration, if the report has it;
- the file path.

It runs nothing, spawns nothing and makes no network call. Combining it with `--once`, `--check`, `--next` or `--dry-run` is an error.

## Acceptance criteria
- Reports that are missing, empty or malformed are skipped and counted ("skipped 2 unreadable").
- Ordering is correct across jobs and same-day `-n` files.
- N validation matches the `--next` style.
- Output never contains report bodies, only header fields.
- Existing tests stay green and unedited.
