# TM2-25 · trade-mcp · search also matches API_HEADER rules
Branch: tm2/TM2-25        Base: main **after PR #45 (O-5) merges**        Owner: TM2

## Why
`searchApi` (src/sdk/search.ts) only matches API_DOCS entries. The header holds the risk rules, the code rules and the denial texts, and it appears only for an empty query. So a search for "risk denied", "market closed" or "kill switch" never shows the rules an AI most needs. The O-5 edge tests documented this gap.

## Files you may touch
- `trade-mcp/src/sdk/search.ts`
- `trade-mcp/test/tm2_25_search_header.test.ts` (new)

## What to build
- With a non-empty query, also match the header line by line. When any header line matches a token, prepend a `// Rules:` block with up to 8 matching header lines (verbatim), placed before the rendered entries.
- Keep the 20-entry cap for entries.
- Readonly scope: header lines that mention trading may still be shown. They are rules, not capabilities.
- When nothing matches, the existing "No API entries match" message stays, unless header lines matched.

## Acceptance criteria
- "risk denied", "kill switch", "market closed" and "maxShortOptionQtyPerOrder" return the relevant header lines.
- Existing search tests stay green. If a pinned test freezes the exact output for a query that now also matches the header, your test writer updates it (an AC change).
- Output for a query that matches no header line is byte-identical to today.
