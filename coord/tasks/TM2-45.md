# TM2-45 · bt-service · central ns normaliser in the shared load path
Branch: tm2/TM2-45        Base: main (after #69 TM2-41 merges)        Owner: TM2
Owner approval: chat 2026-11-28 04:35 IST, item 1. Needed before TM2-43 (lifting the pandas pin).

## Why
The TM2-41 review (coord/reviews/TM2-41.md) found that under pandas 3, about 20 loaders still return `datetime64[us]` indexes. They include ccxt's OHLCV index (`pd.to_datetime(..., unit="ms")`), yfinance, yahoo, india_broker, akshare, alphavantage and others. Per-loader edits are fragile; one normalisation where every loader's output passes is not.

## Files you may touch (≤5)
- The shared load path that every loader's frames pass through, e.g. the registry or base `fetch`/`load` wrapper in `bt-service/vibe_bt/backtest/loaders/base.py` or `registry.py`. Find it and name it in the report. **No per-loader edits**, except:
- `bt-service/vibe_bt/backtest/loaders/industry_loader.py` (~246-254): its int64 comparison gets `as_unit("ns")` (from the TM2-42 review).
- `bt-service/tests/test_tm2_45_ns_normaliser.py` (new), written by your **test writer**.

## What to build
- One helper, `_to_ns_index(df)`: if the index is a `DatetimeIndex`, return the frame with `index.as_unit("ns")`, tz preserved. Otherwise return it unchanged. Call it once on every frame the shared path returns.
- It must work on pandas 2.3 (a no-op) and 3.x. Values are unchanged. Don't touch columns (a datetime column only if the loaders' contract makes it the time axis; check and report).

## Acceptance criteria
- Under pandas 3, every registered loader's output, through the shared path, has an ns index. Test this with a fake loader returning a us index, plus the real ccxt path with mocked exchange data.
- Pandas 2.3: the full suite is green, values are unchanged, and warnings are ≤ main's.
- No warning filters.

`cd bt-service && uv run pytest -q` and `uv run --with "pandas>=3,<4" python -m pytest -q tests/test_tm2_45_ns_normaliser.py` (use `python -m pytest`).
