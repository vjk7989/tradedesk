# TM2-38 · bt-service · walk-forward keeps completed folds when a later fold fails
Branch: tm2/TM2-38        Base: main (after #63 TM2-31)        Owner: TM2

## Why
`bt_service/walkforward.py` returns `{"ok": False, "error": ...}` with **no folds** when a later fold fails: either "no candidate produced a finite <metric>" (~line 144) or "test run failed" (~line 164). For options this is the normal case once the range passes the last expiry, so every finished fold is thrown away. The time-budget path (~lines 123 and 149) already returns `folds`.

- `bt-service/tests/test_tm2_38_wf_partial.py` (new)

- Don't add a summary or oos_equity for partial results unless the budget path does; match it exactly.
- Error texts are unchanged.

- The success path is byte-identical.
