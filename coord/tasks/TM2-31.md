# TM2-31 · bt-service · walk-forward works with india_options and composite baskets
Branch: tm2/TM2-31        Base: main        Owner: TM2

## Why
TM-14 added india_options and composite support, but `bt_service/walkforward.py` predates it. Nobody has checked that the folds work for options: expiry inside a test window, or a train window that ends after an expiry.

## Files you may touch
- `bt-service/bt_service/walkforward.py`: fixes only, if needed.
- `bt-service/tests/test_tm2_31_wf_options.py` (new)

## What to build
- Write tests that run walk-forward over:
  - (a) a single CE symbol whose expiry falls inside fold 2's test window;
  - (b) an equity + option composite;
  - (c) options with too few bars per fold.
- Use local fixtures with a mapped `underlying`.
- Fix walkforward.py only where a test exposes a real bug. Example: a fold must never carry an expired option into the next fold's data, and no look-ahead across the fold boundary is allowed.
- If no fix is needed, the PR is tests only. Say so in the report.

## Acceptance criteria
- Each fold's chosen params and test metrics are deterministic. Assert them exactly on the fixtures.
- The expiry settles inside the fold where it falls.
- A fold with too little data gives a clear warning, not a crash.
- The full bt-service suite stays green.

## Verify
`cd bt-service && uv sync && uv run pytest -q`
