# TM2-39 · bt-service · walk-forward warns on thin folds

## Why
A fold whose train or test window has very few bars runs silently and scores. TM2-31 shows 5 option bars scoring with `warnings == []`. Results from such folds are statistically meaningless, and the caller should be told.

## Files you may touch
- `bt-service/bt_service/walkforward.py`
- `bt-service/tests/test_tm2_39_wf_thin.py` (new)

## What to build
- After each train and test run, if the run has fewer than `MIN_FOLD_BARS` bars (a module constant, default 10; document it), append `fold <i>: thin <train|test> window (<n> bars < 10)` to `warnings`.
- Count bars from the run's equity points or the data the run already returns; don't add a data fetch.
- Warnings only: never change scores, selection or ok.

## Acceptance criteria
- A thin train window gives exactly one train warning for that fold; thin test the same.
- Normal folds give no new warnings.
- Wording follows the existing `fold <i>: ...` prefix.
- TM2-31's test asserts `warnings == []` for a 5-bar train window (`tests/test_tm2_31_wf_options.py`). It is updated by your **test writer** (an AC change).
- docs/backtesting.md's walkForward section may need one line; note the line in your report rather than editing the doc.
