# TM-13 · trade-mcp · persist OAuth login state across restarts
Branch: tm/TM-13        Base: main (latest)        Owner: TM1

## Problem (a known limit in hand-off.md)
`src/oauth/provider.ts:73-78` keeps `codes` (authorization codes, 10-min TTL) and `pending` (login requests) in memory only. The login rate limiter in `src/oauth/login.ts` is also in memory. A restart breaks any login in progress and resets the 5-tries-per-15-min limit, so restarting the service is a way around the lockout.

## Files you may touch
- `trade-mcp/src/oauth/provider.ts`
- `trade-mcp/src/oauth/login.ts`
- New: `trade-mcp/test/tm13_oauth_persist.test.ts`

## What to build
1. Persist `codes`, `pending` and the per-IP failed-login counters into the existing `DATA_DIR/oauth.json`:
   - hash the keys: code, rid and IP each by sha256;
   - keep mode 0600;
   - write atomically (temp + rename), as the token store already does.
2. On load, drop expired entries. A corrupt file starts empty, as today, and the static `MCP_TOKEN` keeps working.
3. Never store plaintext codes, rids, IPs, PKCE verifiers or password material.

## Acceptance criteria
- A restart between `/authorize` and `/login` → the login still completes.
- A restart between `/login` and `/token` → the code exchange works exactly once; the single-use rule survives the restart.
- 5 failures, then a restart, then a 6th attempt → 429. The 15-minute window expiry still works on a fake clock.
- `oauth.json` contains none of the raw codes, rids, IPs or the password hash.
- Existing OAuth tests stay green; don't edit them.
