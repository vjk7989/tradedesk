## What to build
1. `deploy/backup.sh [DEST_DIR]` (bash, `set -euo pipefail`):
   - Uses `docker run --rm -v <volume>:/src:ro -v DEST:/dst alpine tar czf ...` to archive each named volume into `DEST/<UTC-timestamp>/<volume>.tgz`.
   - Copies `deploy/.env`, `deploy/openalgo.env` and `deploy/risk.json` if they exist.
   - Writes a `MANIFEST.txt` with sha256 sums.
   - Sets every file in the backup to `chmod 600` and the directory to 700.
   - Keeps the last N backups (`KEEP`, default 14) and deletes older ones.
   - Never prints file contents.
   - The volume name prefix comes from `COMPOSE_PROJECT_NAME`, default `deploy`.
2. `deploy/restore.sh <BACKUP_DIR>`:
   - Verifies the MANIFEST sha256 sums before doing anything.
   - Refuses to run while the stack is up (`docker compose -f deploy/docker-compose.yml ps -q` is non-empty) unless `--force` is given.
   - Restores each volume archive into its volume, and copies the env and risk files back. Before overwriting any existing file, it moves it to `*.pre-restore`.
3. `docs/backup.md` (no more than 60 lines):
   - what is backed up and why it is secret;
   - a cron example (daily at 02:15 IST);
   - an off-site copy suggestion (rsync to another host, no specific cloud vendor);
   - restore steps;
   - a restore-drill checklist.

## Acceptance criteria
- `shellcheck`-clean if shellcheck is available; otherwise `bash -n` clean.
- `deploy/test_backup.py` (pytest) runs both scripts with a **fake `docker` on PATH**: a small stub script that records its args and creates the expected tar files. Do not require real Docker. Assert:
  - the folder layout, MANIFEST correctness and permissions (skip the permission checks on Windows);
  - retention (create 16 backups with KEEP=14 → 14 remain);
  - restore refuses on a sha mismatch and refuses while the stack is "up" (the fake docker returns ids) unless `--force`;
  - the `.pre-restore` copies are made;
  - no file content appears in stdout or stderr.
