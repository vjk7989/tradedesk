# TM2-60 · bt-service · audit datetime columns vs int64 math
Branch: tm2/TM2-60        Base: main        Owner: TM2
Owner approval: chat 2026-11-28 08:47 IST, item 4.

## Why
TM2-45 normalises loader-returned **indexes** to ns. A datetime **column** (not the index) that reaches int64 math (`.astype("int64")`, `.view("i8")`, `.asi8`, `.value`, `to_numpy(dtype="int64")`, epoch arithmetic) would still be unit-dependent under pandas 3.

## Files you may touch
- `bt-service/tests/test_tm2_60_datetime_columns.py` (new), written by your **test writer**.
- Source (≤3 files) ONLY if the audit finds a real unit-dependent column path. Fix it with `as_unit("ns")` and identical values, and explain it in the report.
- `coord/reports/TM2-60.md`.

## What to do
1. Audit `bt-service/vibe_bt` and `bt-service/bt_service` for datetime **columns** produced by loaders, engines, metrics or walkforward, and for every int64 conversion of datetimes. List each site (file:line) with a verdict: index (covered by TM2-45), column (unit-safe because …), or column (unit-dependent, which is a bug).
2. Pin the result with a test. For each column path that reaches int64 math, feed `us` and `ns` inputs and assert identical results. Also assert that loaders' outputs carry no datetime64 columns, if that's the contract.

## Acceptance criteria
- The report has the full site list with verdicts.
- The test passes on pandas 3.1.1, and the full suite is green.
