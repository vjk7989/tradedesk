# O-14 · trade-mcp · api-docs: tell the AI the sandbox limits (ADR-18/19, O-10)
Branch: own/O-14        Base: main        Owner: OWNER

## Why
The AI client only learns the sandbox limits by hitting them. Add one compact rule block to API_HEADER (searchable through TM2-25's Rules matching), so scripts are written within the limits.

## Files you may touch
- `trade-mcp/src/sdk/api-docs.ts`: API_HEADER only (one block, up to about 6 short lines).

## What to state (every number and string verbatim from code; cite file:line in the report)
- Memory per run: the default `memoryBytes`. On exceeding it the run fails with "memory limit exceeded". Keep data small and aggregate inside bt-service.
- No ArrayBuffer, TypedArray, DataView, Atomics or WebAssembly; use plain arrays.
- Binding argument cap (1 MB JSON) and result cap (min(4 MB, memoryBytes/4)), with their exact error texts. Request fewer bars or a shorter range.
- Concurrency: at most EXECUTE_MAX_CONCURRENT runs (default 4). On "busy: too many concurrent executes, retry shortly", retry after a short wait. Don't fire many executes in parallel.
- Timeout: EXECUTE_TIMEOUT_MS (default 60000). Code size is capped at 100 KB.

## Acceptance criteria
- Every number and error string matches the code.
- Pinned api-docs baseline tests (o1/o7/tm2_25) are updated by the test writer (an AC change). Don't edit them.
