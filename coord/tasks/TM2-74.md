# TM2-74 · agent-runner · interval schedules (`everyMinutes`)
Branch: tm2/TM2-74        Base: main **after #116 (TM2-73) merges**        Owner: TM2

## Why
A crypto paper-trading job wants to run every N minutes. Today a schedule is a list of days plus one `HH:MM` (jobs.ts:10-14, 46-52).

## Files you may touch
- `agent-runner/src/jobs.ts`: schema and parse.
- `agent-runner/src/scheduler.ts`: next-run logic.
- `agent-runner/test/tm2_74_interval.test.ts` (new)
- `agent-runner/README.md`: the schedule section.

## What to build
- An optional `schedule.everyMinutes` (integer, 5..1440). It is mutually exclusive with `time`; giving both, or neither, is a parse error with a clear message.
- `days` still filters which days the job runs.
- Runs are aligned to the job's tz, minute 0 of each day, then every N minutes. Optional `between: ["HH:MM","HH:MM"]` limits the window, e.g. market hours.
- Overlap rule: if the previous run is still going, skip this slot and log it. Runs never stack.
- `--next N` and `--dry-run` show the interval runs correctly.

## Acceptance criteria
- With a fake clock:
  - every 30 min across midnight, a weekend filter and the IST/UTC boundary;
  - a `between` window;
  - an overlap skip;
  - invalid values: 0, 4, 1441, non-integer, both or neither of `time`/`everyMinutes`.
- Existing `time` schedules behave byte-identically.
- Existing tests stay green. Pinned schema-text tests are an AC change for your test writer.
