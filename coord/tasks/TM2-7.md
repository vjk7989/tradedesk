## What to build
One workflow running on `pull_request` (to main) and `push` (to main), on `ubuntu-latest`, with read-only `permissions: contents: read`. Four jobs run in parallel:
1. **trade-mcp:**
   - `actions/setup-node` with Node 22 and npm cache;
   - then `npm ci && npx vitest run && npx tsc --noEmit && npm run build`.
2. **agent-runner:** the same steps in `agent-runner/`, plus `node dist/main.js --help`.
3. **bt-service:**
   - `astral-sh/setup-uv` (pin a version);
   - then `uv sync && uv run pytest -q`;
   - timeout 20 min.
4. **deploy:**
   - `docker compose -f deploy/docker-compose.yml --env-file deploy/.env.example config -q`;
   - `uv run --with pytest --with pyyaml pytest -q deploy/`.

Rules:
- Pin every action to a full commit SHA, with a version comment. No `@main`.
- Add `concurrency` that cancels superseded runs per PR.
- No secrets are used, and none are needed.
- Don't run `e2e/smoke.mjs` in CI yet.

## Acceptance criteria
- YAML is valid: `python -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))"`.
- `actionlint` is clean, if you can install it locally; otherwise say so.
- The workflow actually runs green on your PR. Push the branch and check the Actions tab. If a suite fails on Linux only, report it; don't change product code.
