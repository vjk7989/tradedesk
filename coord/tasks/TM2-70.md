# TM2-70 · bt-service · tz-explicit point-in-time joins (no look-ahead from tz mixing)
Branch: tm2/TM2-70        Base: main        Owner: TM2        Approved: owner 11:35 IST · **HIGH priority**

## Finding (TM2-67 dev, TM2-68 tests)
Joining tz-aware dates against a naive bar index can silently create look-ahead. Look-ahead is the worst class of backtest bug.
- `fundamentals_loader._ffill_pit`: an all-tz-suffixed `filed` (`…Z` or `+05:30`) against a naive index unions into an unsorted object index, and `ffill` then carries the latest value backwards. A 01-05 filing appears on 01-02..04, on main as well. This is pinned as a strict xfail in `bt-service/tests/test_tm2_68_ffill_pit_formats.py`, whose reason string wrongly says "TM2-69 proposal".
- `_ffill_pit` against a **tz-aware** index silently misaligns: a filing dated 02-29 shows on bar 02-28 (TM2-67 dev).
- `industry_loader.py` and `rsshub_events.py` may shift by a day on tz-aware indexes. Not yet probed.
- `fundamentals_loader.py:103-105` parses raw SEC `period_start`, `period_end` and `filed` with inferred formats. Harmless today (SEC is ISO), but it's the same hazard class.

No current source triggers these. They must still be impossible, not just unreached.

## Files you may touch
- `bt-service/vibe_bt/backtest/loaders/fundamentals_loader.py`, `industry_loader.py`, `rsshub_events.py`. Add a small shared helper module under `loaders/` if that's the cleanest approach.
- Do not change `tushare_fundamentals.py` behaviour (TM2-67 already handles it as CN-local). Reuse its approach, and refactor it onto a shared helper only if the result is byte-identical.
- Tests belong to your test writer.

## What to do
- **One explicit rule before any union, merge, reindex or comparison of dates against the bar index:** normalise both sides to the same representation, so an object-dtype index can never form.
  - Choose the market-calendar rule per loader and state it. US SEC filings use the US/Eastern calendar date. China and tushare use CN-local (TM2-67). rsshub and industry use whatever their sources mean.
  - A tz-aware bar index is converted to that market tz and made naive for the key. A naive bar index is taken as already being market-local, as today.
  - The returned frame keeps the caller's exact index.
- Add a guard after every such join: if the resulting index is object dtype or not monotonic where it must be, raise a clear internal error. Never silently ffill.
- Parse `fundamentals_loader.py:103-105` explicitly (`format="ISO8601"`), the same way TM2-68 did.
- Naive inputs must stay **byte-identical** to main in every loader. Prove it.

## Acceptance criteria
- No loader can show a value before its point-in-time date, for naive, UTC and market-tz indexes and for tz-suffixed source dates. Each loader has a no-look-ahead test at the day boundary.
- The TM2-68 strict xfail becomes a passing test, and its reason string is fixed.
- Naive results are byte-identical to main, and the full suite is green with no new warnings.
- There is a pre-fix failure proof.
