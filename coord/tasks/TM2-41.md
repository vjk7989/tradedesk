# TM2-41 · bt-service · P3-A: normalise loader datetime units to ns
Branch: tm2/TM2-41        Base: main        Owner: TM2
Owner approval: chat 2026-11-28 03:55 IST, item 1 (policy: **normalise to ns**). Source: coord/reports/TM2-34.md.

## Why
Under pandas 3, loaders and `_TIMEFRAME_DELTA` produce `us`-unit indexes and timedeltas. The engine compares int64 epochs (`engines/base.py:298`, `rebalance_mask.py:67,95`) and assumes `ns`. Pinning the unit at the loader boundary makes behaviour identical on pandas 2.3 and 3.x.

## Developer: files you may touch (source only)
- `bt-service/vibe_bt/backtest/loaders/base.py`: `resample_bars` output index is `datetime64[ns]` (tz preserved).
- `bt-service/vibe_bt/backtest/loaders/local_loader.py`: output index is ns.
- `bt-service/vibe_bt/backtest/loaders/ccxt_loader.py`: `_TIMEFRAME_DELTA` values are `Timedelta` with ns unit.

## Test writer (separate agent): files
- `tests/test_tm8_edge.py` and `tests/test_tm15_warnings_edge.py`: unit and dtype assertions.
- `test_capture_mechanism_sees_generic_timedelta_warning`: remove, or xfail with a reason, since pandas 3 no longer warns.
- New `tests/test_tm2_41_units.py`: every loader output and `_TIMEFRAME_DELTA` is ns, under the installed pandas.

## Acceptance criteria

- Under pandas 3, `uv run --with "pandas>=3,<4" python -m pytest -q tests/test_tm8_edge.py tests/test_tm15_warnings_edge.py tests/test_tm2_41_units.py` has 0 failed. Use `python -m pytest`; plain `pytest` silently runs pandas 2.
